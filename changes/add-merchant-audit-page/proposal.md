# Proposal: 新增商户资料审核页面

## 1. Original Request

使用 yeepay-page-skill，帮我新增一个 Boss Ledger 商户资料审核页面。页面需要符合 Boss Ledger 主题规范，输出页面 HTML 先测试预览，前端语言先不用输出。

## 2. Requirement Understanding

为 Boss Ledger 后台新增“商户资料审核”页面，供审核人员查询商户资料审核任务、查看资料详情、执行通过或驳回操作，并在静态 HTML 中提供可预览的页面效果。

## 3. Target Theme

- Theme: boss-ledger
- Reason: 需求明确包含 Boss Ledger、商户资料、审核后台场景，按主题选择规则使用 `specs/themes/boss-ledger.md`。

## 4. Background

商户资料审核涉及商户主体信息、证照资料、联系人、结算信息等关键资料。需要提供统一审核入口，减少审核遗漏，并让审核人员能快速定位待审核任务和完成处理。

## 5. Goals

- 提供商户资料审核任务查询和列表展示能力。
- 支持查看商户提交资料和审核记录。
- 支持审核通过、审核驳回，并对高风险操作进行确认。
- 审核完成后能明确反馈处理结果。
- 输出静态 HTML 预览文件，便于先行验证页面结构和主题符合度。

## 6. Users / Roles

- 审核人员：查询、查看和处理商户资料审核任务。
- 运营人员：查看审核状态和审核结果。
- 系统管理员：具备查看和管理权限配置的能力。

## 7. Scope

### In Scope

- 商户资料审核查询条件。
- 审核任务列表。
- 审核状态展示。
- 商户资料详情抽屉。
- 审核通过确认。
- 审核驳回原因填写。
- loading / empty / error 的页面状态说明。
- 静态 HTML 预览页面。

### Out of Scope

- 真实后端接口接入。
- React / TypeScript 生产代码。
- 权限系统真实接入。
- 文件预览、OCR、影像件在线比对。
- 批量审核。
- 审核规则引擎配置。

## 8. Business Object

核心业务对象：商户资料审核任务。

关联对象：

- 商户
- 商户主体资料
- 证照资料
- 联系人资料
- 结算资料
- 审核记录

## 9. Core Workflow

1. 审核人员进入“商户资料审核”页面。
2. 按审核单号、商户编号、商户名称、资料类型、审核状态、提交时间查询任务。
3. 系统展示匹配的审核列表。
4. 审核人员点击“查看”打开详情抽屉。
5. 审核人员点击“审核”打开审核弹窗。
6. 审核人员选择“通过”或“驳回”。
7. 驳回时必须填写驳回原因。
8. 系统展示操作结果，并更新列表状态。

## 11. Status

| Status | Meaning | Available Actions |
|---|---|---|
| 待审核 | 任务待审核人员处理 | 查看、审核 |
| 审核通过 | 资料审核已通过 | 查看 |
| 审核驳回 | 资料审核未通过，需商户重新提交 | 查看 |
| 处理中 | 审核提交后系统处理中 | 查看 |
| 已失效 | 任务因商户重新提交或状态变更失效 | 查看 |

## 12. Permissions

- 审核人员可查看审核列表、查看详情、执行通过或驳回。
- 运营人员可查看列表和详情，不可执行审核。
- 系统管理员可查看全部任务，并配置角色权限。
- 审核通过、审核驳回必须二次确认。
- 无审核权限时，“审核”操作不可见或置灰并展示原因。

## 13. Edge Cases

- 查询无结果时展示空状态。
- 网络错误时展示错误反馈并允许重试。
- 数据加载失败时保留查询条件。
- 审核提交失败时展示失败原因。
- 驳回未填写原因时阻止提交。
- 审核任务状态已变化时提示刷新后重试。
- 用户无权限时隐藏或禁用审核操作。
- 重复提交时按钮进入 loading 并阻止二次点击。

## 14. Acceptance Criteria

- 当审核人员输入商户编号并点击“查 询”时，页面应返回匹配的审核任务列表。
- 当列表无数据时，表格区域应展示空状态。
- 当审核人员点击“查看”时，页面应打开商户资料详情抽屉。
- 当审核人员点击“审核”时，页面应打开审核操作弹窗。
- 当审核人员选择“驳回”且未填写驳回原因时，系统应阻止提交并提示“请输入驳回原因”。
- 当审核人员确认通过或驳回时，系统应展示二次确认。
- 当审核操作成功时，系统应展示成功反馈并更新列表状态。
- 当用户无审核权限时，审核操作应不可见或不可点击。

## 15. Assumptions

- 当前页面平台明确为 Boss Ledger。
- 本次只输出静态 HTML 预览，不输出 React / TypeScript 生产代码。
- 审核详情使用 Drawer，审核处理使用 Modal。
- 列表默认展示待审核任务。
- 审核状态和模拟数据用于预览，后续需对接真实接口。
