# Proposal: Boss Ledger 酒店民宿运营后台

## 1. Original Request

使用 yeepay-page-skill，新增一个 Boss Ledger 酒店民宿运营后台。需求包含三个一级导航：经营数据总览、客房订单管理、门店渠道与房型管理；共六个页面：经营大盘首页、房客经营分析、全部订单列表、前台入住工作台、门店房型管理、OTA 分销渠道管理。

## 2. Requirement Understanding

本次需求面向酒店 / 民宿连锁或多门店运营团队，在 Boss Ledger 后台内集中查看经营数据、分析房客结构、处理客房订单与前台入住、维护门店房型和 OTA 分销渠道。页面组需要兼顾数据看板、查询列表、工作台和配置管理。

## 3. Target Theme

- Theme: Boss Ledger
- Reason: 需求明确包含 Boss Ledger、酒店民宿运营后台、订单管理、门店房型管理、分销渠道管理等运营后台关键词，按主题选择规则使用 `specs/themes/boss-ledger.md`。

## 4. Background

酒店民宿运营涉及客房收入、入住订单、在店客人、分销结算、房型库存、前台入住和客诉待办等高频事项。若数据分散在 PMS、OTA、财务和客服系统中，运营人员需要跨系统核对，影响经营决策与前台处理效率。本页面组用于把核心经营、订单、入住和渠道管理能力收敛到 Boss Ledger 后台。

## 5. Goals

- 提供经营大盘首页，支持按时间、门店、房型品类查看收入、入住、在店客和待结算分销款。
- 提供房客经营分析，帮助运营判断客源渠道、地域、入住峰值、长短住消费和高复购房型。
- 提供全部订单列表，支持多条件查询、周期汇总、单行处理和批量处理。
- 提供前台入住工作台，支持身份证扫码、手机号和订单号检索，沉淀实时入住流水与异常订单台账。
- 提供门店房型管理，维护门店营业状态、房型价格、库存、设施和售卖状态。
- 提供 OTA 分销渠道管理，维护渠道扣点、营收占比、待结算佣金和对账结算流程。

## 6. Users / Roles

- 酒店运营人员：查看经营数据、分析房客结构、处理订单和客诉待办。
- 前台人员：办理入住、查询预约、记录入住流水和处理异常订单。
- 财务人员：查看待结算分销款、待结算佣金、发起渠道对账结算。
- 门店管理员：维护门店营业状态、房型库存、房价和上下架。
- 系统管理员：维护渠道、权限、导出能力和高风险操作审批。

## 7. Scope

### In Scope

- 三个一级导航和六个页面的信息架构。
- 每个页面的筛选条件、核心指标、图表、榜单、台账、列表和操作。
- 查询、重置、导出、批量处理、二次确认、弹窗、抽屉、Tabs 切换和菜单切换的预览交互。
- Boss Ledger 固定框架：顶部信息栏、一级导航、左侧导航、Tabs 页面标题区、内容区、footer。

### Out of Scope

- 真实 PMS、公安旅业、身份证读卡器、短信网关、支付退款、OTA API 和财务结算接口联调。
- 真实 Excel 文件生成与下载服务。
- 真实权限中心、审批流和操作日志服务。
- 正式 React + TypeScript 工程代码落库。

## 8. Business Object

经营指标、入住订单、房客、客房房型、门店、入住流水、异常订单、客诉工单、企业协议、OTA 渠道、分销账单、渠道佣金、渠道对账结算单。

## 9. Core Workflow

1. 用户进入 Boss Ledger 酒店民宿运营后台，选择一级导航和左侧页面。
2. 数据分析类页面通过轻量筛选条切换时间、门店、房型品类或客源渠道，页面自动刷新指标和图表。
3. 查询列表类页面通过查询区设置订单、门店、房型、入住日期、手机号、渠道等条件，查看汇总和列表。
4. 前台人员在入住工作台使用身份证扫码、手机号或订单号检索预约订单并办理入住。
5. 运营或财务人员对订单、异常、房型、门店和渠道执行单行或批量操作。
6. 退款、批量处理、门店停业、渠道对账结算等高风险操作通过二次确认并反馈结果。

## 11. Status

| Status | Meaning | Available Actions |
|---|---|---|
| 待入住 | 已预约但未办理入住 | 查看详情、修改入住日期、推送入住提醒、发起退款 |
| 已入住 | 已办理入住且仍在店 | 查看详情、办理续住、发起退款 |
| 已离店 | 已完成退房 | 查看详情、导出 |
| 已退款 | 订单已退款完成 | 查看详情 |
| 已过期 | 预约未入住且超过入住窗口 | 查看详情、批量处理过期订单 |
| 重复入住 | 同一证件或订单重复办理入住 | 查看异常、拦截处理 |
| 营业中 | 门店正常售卖和接待 | 修改资料、暂停营业、新增房型、查看数据 |
| 装修暂停 | 门店暂停售卖或接待 | 修改资料、恢复营业 |
| 上架 | 房型可在渠道或前台销售 | 修改房价、下架、查看经营数据 |
| 下架 | 房型不可售 | 修改房价、上架 |
| 合作中 | OTA 渠道正常售卖 | 修改扣点、房型上下架、发起对账结算 |
| 暂停合作 | OTA 渠道暂停售卖 | 修改扣点、恢复合作 |

## 12. Permissions

- 经营数据查看：运营、门店管理员、财务可查看授权门店范围内数据。
- 订单导出、房客分析导出和入住流水导出：需要运营主管或财务权限。
- 发起退款、批量处理过期订单、渠道对账结算：需要二次确认，正式系统可叠加审批或密码校验。
- 修改房价、上下架房型、开关门店营业状态、修改渠道扣点：需要门店管理员或系统管理员权限并记录操作日志。
- 身份证扫码和入住办理：仅前台人员和门店管理员可操作。

## 13. Edge Cases

- 查询无结果时展示空状态，不清空筛选条件。
- 图表数据加载失败时展示图表异常说明，不影响统计和列表模块查看。
- 未选择订单时点击批量操作提示先选择记录。
- 已退款、已离店或已过期订单禁用不适用操作。
- 门店处于装修暂停时不允许新增上架房型。
- 房型库存为 0 时可保留房型但前台和渠道不可售。
- 扣点比例超出渠道合同约定范围时阻止保存。
- 身份证扫码失败时允许切换手机号或订单号检索。
- 状态被他人更新时提示刷新后重试。

## 14. Acceptance Criteria

- 一级导航包含经营数据总览、客房订单管理、门店渠道与房型管理。
- 六个页面均可通过左侧导航进入，Tabs 标题随页面切换。
- 经营大盘首页展示需求指定筛选、四个核心指标、双趋势折线图、渠道占比、房型营收排行、门店入住率排行和待办统计。
- 房客经营分析展示筛选、四个核心指标、24 小时入住分布、地域分布、长短住消费对比、高复购房型 TOP，并提供 Excel 导出入口。
- 全部订单列表展示多维筛选、四个周期汇总指标、订单字段、单行操作和批量操作。
- 前台入住工作台支持三种检索方式、今日统计、实时入住流水、异常订单台账和每日入住流水导出。
- 门店房型管理支持状态 / 楼层筛选、门店汇总、房型列表和门店 / 房型维护操作。
- OTA 分销渠道管理支持合作状态筛选、渠道汇总、营收占比、渠道列表和渠道对账结算操作。
- 预览页面符合 Boss Ledger 主题，不混用 YOP、营销页或开放平台文档风格。

## 15. Assumptions

- 默认当前业务日期为 2026-07-09。
- “酒店民宿运营后台”按多门店、多房型、多 OTA 渠道经营模型设计。
- “待结算分销款”和“待结算佣金”均为渠道维度财务待处理金额，正式系统应与财务口径确认。
- 预览数据为 mock 数据，仅用于页面评审。
- Boss Ledger Logo 使用当前变更包内临时 SVG 占位，正式项目应替换为官方品牌资产。
