# 需求方案：Boss Ledger 智能音箱电商运营后台

## 1. 原始需求

使用 yeepay-page-skill，新增 Boss Ledger 智能音箱电商运营后台，包含音箱经营数据总览、音箱订单运维管理、店铺渠道与音箱商品管理三组一级导航与对应页面。

## 2. 需求理解

本次需求属于 Boss Ledger 运营后台新增业务模块，面向智能音箱电商经营、订单运维、渠道分销与商品库存管理。页面需要帮助运营人员统一查看经营收益、订单量、渠道结构、单品排行和待办工单，并支持订单全生命周期运维与店铺 / SKU 商品维护。

## 3. 目标主题

- 主题：Boss Ledger
- Theme source：`specs/themes/boss-ledger.md`
- Routing reason：需求明确包含 Boss Ledger、运营后台、订单管理、经营数据首页和商品管理，按 `specs/theme-routing.md` 选择 Boss Ledger。
- Mixed Theme Sources：No，未读取或混用 YOP 开放平台主题。

## 4. 背景说明

智能音箱电商业务同时覆盖自营店、授权分销店、OTA 平台、私域、线下门店和企业采购渠道。运营需要在同一后台内监控收益、销量、库存、结算和售后待办，减少跨系统查询与工单漏处理。

## 5. 业务目标

- 提供统一经营大盘，快速识别交易额、订单量、SKU 现货和分销待结算风险。
- 支持音箱订单按状态、店铺、品类、日期、手机号和渠道精确检索。
- 支持批量导出、物流通知、超时订单清理和单行订单处理。
- 支持统一维护店铺营业状态、SKU 售价、库存、上下架与仓储库区。

## 6. 使用用户 / 角色

| 角色 | 使用场景 | 核心诉求 | 主要操作 |
|---|---|---|---|
| 电商运营人员 | 日常经营监控、订单处理、商品维护 | 快速发现经营波动与待办 | 查询、导出、修改发货、上下架 |
| 渠道运营人员 | 分销店铺与企业采购跟进 | 识别渠道成交与待结算账款 | 查看排行、核对账单、审核协议 |
| 客服人员 | 售后客诉与退款处理 | 定位订单并发起退款或通知 | 查看详情、发起退款、推送短信 |
| 系统管理员 | 店铺与商品配置维护 | 控制店铺营业和 SKU 状态 | 新增店铺、新增 SKU、营业开关 |

## 7. 业务范围

### 7.1 本期范围

- 音箱经营大盘首页：3 个顶部筛选、经营指标、趋势图、渠道环图、排行和待办。
- 全部音箱订单列表：6 个筛选项、4 个汇总指标、订单表格、单行和批量操作。
- 店铺&音箱商品管理：营业状态和仓储库区筛选、顶部汇总、SKU 商品列表、店铺和商品维护入口。
- 预览页包含 mock 数据、抽屉详情、列设置、分页和操作反馈。

### 7.2 非本期范围

- 不包含真实接口联调。
- 不包含 C 端售卖页面。
- 不包含真实支付、发货、退款、分销结算执行。
- 不修改生产项目源码；本次产出为 change 包和 `preview.html` 评审预览。

## 8. 业务对象

- 经营指标：交易额、订单量、在售 SKU、分销待结算货款。
- 音箱订单：订单编号、用户信息、品类型号、金额、状态、渠道、履约时间。
- 店铺：自营店、授权分销店、企业采购店、营业状态。
- SKU 商品：商品名称、售价、库存、功能、仓储库区、上下架状态。
- 工单：渠道账单、企业采购协议订单、售后客诉工单。

## 9. 核心业务流程

1. 运营进入 Boss Ledger 智能音箱后台。
2. 在经营大盘通过时间、店铺、品类筛选查看经营趋势和待办。
3. 在订单列表输入筛选条件，系统返回订单汇总与明细。
4. 运营查看订单详情，执行延长付款、修改发货、退款、短信通知等动作。
5. 在商品管理页筛选店铺状态和仓储库区，维护 SKU 售价、库存、上下架和店铺营业状态。
6. 高风险操作通过确认弹窗二次确认，成功后给出反馈并保留上下文。
