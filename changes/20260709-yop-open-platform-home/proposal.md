# Proposal: 易宝支付 YOP 开放平台首页页面方案

## 1. Original Request

使用 yeepay-page-skill，帮我做一个 易宝支付YOP开放平台，不用写代码

## 2. Requirement Understanding

用户希望按 `yeepay-page-skill` 规范，为“易宝支付 YOP 开放平台”设计一个面向开发者、商户和合作伙伴的开放平台门户页面。用户明确“不用写代码”，因此本次只输出产品方案和页面设计方案，不生成前端代码，不修改 `open-platform` 工程。

## 3. Target Theme

- Theme: yeepay-开放平台-DESIGN
- Reason: 需求明确包含“易宝支付 YOP 开放平台”，属于 YOP、开放平台、开发者中心、产品文档和接入流程场景，应使用 `specs/themes/yeepay-开放平台-DESIGN.md`。

## 4. Background

YOP 开放平台需要作为易宝支付开放能力的统一入口，帮助访问者快速理解平台能提供什么、适合哪些业务场景、如何开始接入，以及在哪里查看产品文档、API 文档、SDK、开发工具和帮助支持。

页面不是内部运营后台，也不是单一 API 详情页。它应更接近“开放平台门户首页 + 开发者中心入口”，承担品牌认知、能力导航、接入引导和资源分发四类任务。

## 5. Goals

- 让访问者进入页面后快速确认这是“易宝支付 YOP 开放平台”的官方入口。
- 清晰展示支付、账户、分账、出款、行业解决方案、开发工具等开放能力。
- 帮助开发者在首页完成“找能力、看文档、查 API、开始接入”的路径判断。
- 为已入驻商户和合作伙伴提供控制台、密钥、应用、工单和帮助中心入口。
- 保持 YOP 主题的清爽、专业、可信、开发者友好视觉气质。

## 6. Users / Roles

- 开发者：查找 API、阅读接入文档、下载 SDK、查看示例代码、完成联调。
- 商户管理员：了解产品能力、进入控制台、管理应用和密钥、查看接入状态。
- SaaS / ISV / 渠道服务商：评估易宝支付能力与行业解决方案，发起合作咨询。
- 内部支持人员：向外部客户推荐标准接入路径、文档入口和帮助资源。

## 7. Scope

### In Scope

- 开放平台首页信息架构。
- 顶部导航、Hero、全站搜索、能力分类、行业解决方案、开发资源、接入流程、平台优势、更新公告、帮助支持、底部导航。
- 首页关键字段、操作、状态和异常场景设计。
- YOP 主题应用说明和页面质量自检。

### Out of Scope

- 不输出 React / Vue / TypeScript / CSS 等前端代码。
- 生成 `preview.html` 作为页面评审预览文件；该 HTML 不属于正式生产前端代码。
- 不实现真实搜索、登录、控制台、API 调用、SDK 下载和工单提交逻辑。
- 不设计 API 详情页、产品文档详情页、控制台后台页面的完整细节。
- 不修改现有 `open-platform` 工程代码。

## 8. Business Object

业务对象：YOP 开放平台门户能力。

核心信息对象包括：

- 开放能力：收单、账户、分账、出款、跨境、营销、风控、对账等。
- 开发资源：API 文档、产品文档、SDK、示例代码、错误码、回调说明、签名验签、沙箱联调。
- 接入路径：了解方案、申请入驻、创建应用、获取密钥、接口联调、上线验收。
- 平台入口：控制台、文档中心、API 中心、帮助中心、合作咨询。

## 9. Core Workflow

1. 用户进入 YOP 开放平台首页。
2. 用户通过 Hero 区确认平台定位，并选择“开始接入”“查看 API 文档”或“联系咨询”。
3. 用户可以使用全站搜索查找产品、API、错误码、SDK 或接入问题。
4. 用户浏览能力分类，进入具体产品文档或 API 列表。
5. 用户根据自身角色进入商户、服务商、开发者或行业解决方案路径。
6. 用户查看接入流程，理解从入驻到上线的步骤和前置条件。
7. 用户进入开发资源区，下载 SDK、查看示例代码、阅读签名验签和回调说明。
8. 用户查看最新更新和公告，确认接口变更、文档更新或维护提醒。
9. 用户在帮助支持区进入工单、FAQ、客服或合作咨询。

## 10. Fields

| Field | Type | Required | Description | Example |
|---|---|---|---|---|
| 平台名称 | Text | Yes | 首页主标题和品牌识别 | 易宝支付 YOP 开放平台 |
| 平台描述 | Text | Yes | 说明平台价值和服务对象 | 聚合易宝支付开放能力，帮助开发者快速完成支付接入与业务上线 |
| 全站搜索关键词 | Text | No | 搜索产品、API、错误码、SDK、文档 | 小程序支付、分账、RSA、回调 |
| 能力分类 | Category | Yes | 首页核心能力分组 | 支付收单、账户体系、分账结算、企业付款 |
| 能力名称 | Text | Yes | 单个产品或能力入口名称 | 聚合支付 |
| 能力描述 | Text | Yes | 说明能力适用场景 | 支持 App、H5、小程序、扫码等多场景收款 |
| 文档类型 | Tag | Yes | 区分 API、产品文档、指南、工具 | API 文档 |
| 接入步骤 | Step | Yes | 展示接入流程节点 | 创建应用、配置密钥、接口联调 |
| 资源名称 | Text | Yes | 开发资源入口 | Java SDK |
| 更新时间 | Date | No | 文档或公告更新信息 | 2026-07-09 |
| 公告级别 | Status | No | 表示普通更新、重要变更、维护提醒 | 重要 |

## 11. Status

| Status | Meaning | Available Actions |
|---|---|---|
| 推荐 | 高频或主推能力 | 查看文档、查看 API |
| 新增 | 新上线能力、文档或工具 | 查看详情 |
| 已更新 | 文档、SDK 或接口近期有更新 | 查看更新记录 |
| 维护提醒 | 接口、环境或服务存在维护安排 | 查看公告 |
| 即将上线 | 能力已规划但暂未开放 | 预约咨询、关注更新 |

## 12. Permissions

- 未登录用户：可查看首页、产品介绍、公开文档、接入指南、帮助中心和合作咨询入口。
- 已登录商户 / 开发者：可进入控制台、应用管理、密钥管理、沙箱联调和工单入口。
- 未开通产品用户：查看文档时展示开通或咨询引导，不直接进入受限控制台能力。
- 权限不足场景：受限入口应说明原因，并提供“申请开通”“联系支持”或“返回文档”的路径。

## 13. Edge Cases

- 搜索无结果：展示“未找到相关内容”，推荐热门关键词、API 分类和帮助中心入口。
- 搜索加载失败：保留搜索词，提示稍后重试，并提供文档分类入口。
- 文档或 API 暂未开放：展示“即将上线”状态，提供预约咨询或关注更新入口。
- 用户未登录访问控制台：引导登录，并说明登录后可管理应用、密钥和联调信息。
- 权限不足访问产品能力：提示当前账号未开通，提供申请开通或联系支持入口。
- 公告为空：展示近期无重要公告，并保留更新日志入口。
- 移动端窄屏：顶部导航收起为菜单，能力卡片和流程步骤纵向排列。

## 14. Acceptance Criteria

- 页面定位明确，首屏能识别“易宝支付 YOP 开放平台”。
- 页面结构符合 YOP 开放平台主题，不混用 Boss Ledger 运营后台风格。
- 顶部导航、搜索、能力分类、接入流程、开发资源和帮助支持入口完整。
- 主操作清晰，首页只保留少量高优先级 CTA。
- 开发者可以从首页进入 API 文档、产品文档、SDK、示例代码、错误码和接入指南。
- 页面考虑未登录、权限不足、搜索无结果、加载失败、移动端收起等状态。
- 文案准确、克制、专业，不使用营销化空话或无意义占位内容。

## 15. Assumptions

- 本次“做一个易宝支付 YOP 开放平台”理解为开放平台首页 / 门户页设计，而不是完整开放平台系统的所有页面。
- 具体产品名称、API 分类和公告内容基于开放平台常见结构做合理补全，后续可替换为真实业务数据。
- 用户要求“不用写代码”，因此本次跳过正式前端实现文件，但仍输出 `preview.html` 作为评审预览产物。
- 页面视觉应以 `specs/themes/yeepay-开放平台-DESIGN.md` 为准，品牌主色使用 `#1162e6`，整体保持 Light Mode。
