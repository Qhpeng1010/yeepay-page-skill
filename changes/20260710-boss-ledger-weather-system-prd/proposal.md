# 需求方案：Boss Ledger 天气系统原型 PRD

## 1. 原始需求

`/yeepay:prd 做一个天气系统原型`

---

## 2. 需求理解

本次需求是输出一份“天气系统原型”的产品需求文档。用户使用 `/yeepay:prd` 命令，因此按 Yeepay Page Skill 的 Product Only 模式执行，仅生成 `proposal.md`，不生成 `preview.html`，不生成生产前端代码。

用户未指定 C 端天气 App、YOP 开放平台 API 文档或具体生产工程。按默认路由规则，本 PRD 默认面向 Boss Ledger 运营后台，定义一个“天气数据与预警运营后台原型”：用于统一查看城市天气实况、未来预报、天气告警、数据源同步、订阅通知、操作日志和基础配置，帮助运营人员在业务系统中快速识别天气风险并完成人工干预。

---

## 3. 目标主题

- 主题：Boss Ledger
- 选择原因：需求未包含开放平台、API 文档、开发者中心等关键词；“天气系统原型”更适合先落到后台运营、数据监控、预警处理、订阅配置和日志追踪场景。按默认规则选择 Boss Ledger，并在合理假设中说明不混用其他主题规范。

---

## 4. 背景说明

天气信息会影响航旅、出行、物流、门店运营、活动运营、风险提示和客户触达等业务场景。若天气数据分散在外部网站、人工群消息或多个供应商接口中，运营人员难以及时判断某个城市、区域或业务线是否受到强降雨、台风、高温、暴雪、空气污染等天气事件影响。

建设天气系统原型的目标不是替代专业气象业务系统，而是在 Boss Ledger 后台形成一个可评审、可演示、可继续设计和研发拆解的业务原型，覆盖天气数据看板、城市天气列表、预警事件处理、订阅通知配置和数据源同步监控。系统应支持运营人员快速筛选重点城市，查看预警详情，确认影响范围，触发业务通知，并留存处理记录。

---

## 5. 业务目标

- 提供统一天气数据入口，支持运营人员按城市、区域、业务线、天气类型和时间范围查询天气实况与预报。
- 集中展示天气告警事件，帮助运营识别可能影响出行、履约、门店和活动的风险城市。
- 支持预警处理闭环，包括确认、忽略、升级、通知、关闭和处理日志。
- 支持订阅规则配置，使不同业务线可按城市、天气类型和告警级别接收通知。
- 支持天气数据源同步监控，识别接口异常、数据延迟、城市缺失和预警重复。
- 支持天气数据导出、操作留痕和权限控制，满足后台审计和后续研发拆解需要。

## 7. 业务范围

### 7.1 本期范围

- 天气概览看板：展示重点城市天气概况、告警数量、数据同步状态、近 24 小时告警趋势。
- 城市天气查询列表：支持按城市、区域、天气类型、温度区间、降雨概率、告警级别、更新时间等条件查询。
- 城市天气详情抽屉：展示实况天气、未来 7 天预报、小时级预报、空气质量、生活指数、告警记录和数据更新时间。
- 天气告警事件列表：支持查询待处理、处理中、已关闭、已忽略等状态的告警事件。
- 告警处理抽屉：支持确认告警、忽略告警、升级风险、发送通知、关闭告警和填写处理备注。
- 订阅通知配置：支持按业务线、城市范围、天气类型、告警级别和通知渠道配置订阅规则。
- 数据源同步监控：展示天气供应商、同步任务、接口状态、最近同步时间、失败原因和重试操作。
- 基础配置：支持城市分组、重点城市、天气类型、告警级别、业务线和通知渠道配置。
- 权限与日志：覆盖告警处理、通知发送、导出、订阅配置、数据源重试和敏感配置查看。

### 7.2 非本期范围

- 不建设 C 端天气 App、小程序、地图大屏或营销页面。
- 不建设 YOP 开放平台天气 API 文档、SDK、接入指南或开发者控制台。
- 不接入真实气象供应商接口，不承诺气象预报准确性。
- 不实现专业气象模型、雷达图、卫星云图、灾害模拟和气象算法。
- 不处理真实订单改签、退款、履约中断或资金赔付流程。
- 不生成正式 React + TypeScript 生产代码，不生成 `preview.html`。

## 8. 业务对象

- 城市天气记录：城市、区域、天气现象、温度、湿度、风力、降雨概率、空气质量和更新时间。
- 天气预报记录：未来日期、天气现象、最高温、最低温、降雨概率、风向风力和预报来源。
- 小时级预报：小时、温度、天气现象、降雨概率、风速、体感温度。
- 天气告警事件：告警编号、城市、告警类型、级别、影响时间、影响范围、状态和处理人。
- 告警处理记录：确认、忽略、升级、通知、关闭等操作及备注。
- 订阅规则：业务线、城市范围、天气类型、告警级别、通知渠道、接收人和启停状态。
- 通知记录：通知方式、接收对象、发送状态、失败原因和发送时间。
- 数据源：供应商名称、接口类型、同步频率、状态、最近同步时间和失败原因。
- 城市配置：城市编码、城市名称、省份 / 区域、是否重点城市、启停状态。
- 操作日志：查询、导出、配置修改、告警处理、数据源重试等操作记录。

## 9. 核心业务流程

### 9.1 天气数据查看流程

1. 用户进入天气概览或城市天气列表。
2. 系统展示重点城市天气、告警数量和数据同步状态。
3. 用户输入城市、区域、天气类型、告警级别或更新时间等条件。
4. 系统返回天气列表，并保留查询条件。
5. 用户点击“查看详情”，系统打开城市天气详情抽屉。
6. 用户查看实况天气、未来预报、小时级预报、空气质量、生活指数和历史告警。

### 9.2 天气告警处理流程

1. 系统从数据源同步到天气告警，生成告警事件。
2. 告警事件进入“待处理”状态，并按城市、级别和业务线匹配订阅规则。
3. 运营人员进入告警列表，筛选待处理或高级别告警。
4. 用户查看告警详情，判断是否影响业务。
5. 用户可执行确认告警、忽略告警、升级风险、发送通知或关闭告警。
6. 系统校验权限和事件状态，成功后更新告警状态。
7. 系统记录操作日志，并展示通知发送结果。

### 9.3 订阅通知配置流程

1. 业务管理员进入订阅通知配置页。
2. 用户新建订阅规则，选择业务线、城市范围、天气类型、告警级别、通知渠道和接收人。
3. 系统校验规则是否重复、接收人是否有效、通知渠道是否可用。
4. 用户保存后，规则进入启用或停用状态。
5. 后续新告警生成时，系统按规则匹配并生成通知任务。
6. 通知成功或失败均写入通知记录。

### 9.4 数据源同步监控流程

1. 系统按配置频率同步天气实况、天气预报和天气告警。
2. 同步成功后更新城市天气记录和同步时间。
3. 同步失败时记录失败原因，并在数据源监控中展示异常。
4. 系统管理员可点击“重试同步”。
5. 重试成功后更新状态；重试失败时保留错误原因并写入日志。

## 13. 状态设计

### 13.1 天气数据状态

| 状态 | 含义 | 可执行操作 |
|---|---|---|
| 正常 | 数据源同步成功，数据在有效期内 | 查看详情、导出 |
| 延迟 | 超过配置阈值未更新，但存在历史数据 | 查看详情、重试同步 |
| 同步失败 | 最近一次同步失败 | 查看失败原因、重试同步 |
| 缺失 | 城市无可用天气数据 | 查看配置、补充城市映射 |
| 停用 | 城市或数据源已停用 | 查看配置、启用 |

### 13.2 天气告警状态

| 状态 | 含义 | 可执行操作 |
|---|---|---|
| 待处理 | 新生成告警，尚未人工确认 | 处理、忽略、查看详情 |
| 处理中 | 已被领取或正在判断影响范围 | 发送通知、升级风险、关闭 |
| 已通知 | 已按订阅规则发送业务通知 | 查看通知记录、关闭 |
| 已忽略 | 人工判断不影响当前业务 | 查看详情、重新打开 |
| 已关闭 | 告警处理完成或影响结束 | 查看详情、查看日志 |
| 通知失败 | 通知任务发送失败 | 重试通知、查看失败原因 |

## 14. 核心操作规则

| 操作 | 触发位置 | 前置条件 | 操作结果 | 风险控制 |
|---|---|---|---|---|
| 查询 | 天气列表、告警列表、数据源列表 | 用户有页面访问权限 | 按条件刷新列表 | 保留查询条件 |
| 导出 | 列表工具栏 | 用户有导出权限 | 生成导出任务 | 记录导出条件、操作人、时间 |
| 查看详情 | 表格操作列主操作 | 用户有查看权限 | 打开详情抽屉 | 敏感配置不展示明文 |
| 确认告警 | 告警处理抽屉 | 告警为待处理或处理中 | 状态变为处理中或已通知 | 必填处理意见 |
| 忽略告警 | 告警处理抽屉 | 告警为待处理 | 状态变为已忽略 | 必填忽略原因 |
| 升级风险 | 告警处理抽屉 | 告警级别较高或影响业务线 | 生成风险标记 | 二次确认并记录原因 |
| 发送通知 | 告警处理抽屉 | 已匹配订阅规则或手动选择接收人 | 生成通知任务 | 记录接收对象和发送内容 |
| 关闭告警 | 告警处理抽屉 | 告警已处理或影响结束 | 状态变为已关闭 | 必填关闭说明 |
| 新增订阅 | 订阅配置页 | 用户有配置权限 | 新增订阅规则 | 校验重复规则 |
| 启用 / 停用订阅 | 订阅配置页 | 用户有配置权限 | 更新规则状态 | 二次确认 |
| 重试同步 | 数据源监控页 | 最近同步失败或延迟 | 触发同步任务 | 防重复提交，记录日志 |
| 修改数据源 | 数据源配置页 | 系统管理员权限 | 更新数据源配置 | 高风险配置二次确认 |

## 15. 权限要求

- 页面访问：仅授权运营、客服、风控、业务管理员和系统管理员可访问。
- 天气查看：运营、客服和风控可查看天气实况、预报和告警摘要。
- 告警处理：仅运营人员、风控人员和授权主管可确认、忽略、升级或关闭告警。
- 通知发送：运营人员可发送业务通知；批量通知或跨业务线通知需要主管权限。
- 订阅配置：仅业务管理员和系统管理员可新增、编辑、启用或停用订阅规则。
- 数据源配置：仅系统管理员可维护数据源、同步频率和城市映射。
- 导出权限：天气明细、告警明细、通知记录和操作日志导出需独立权限。
- 日志查看：管理员可查看全量日志；普通用户仅查看与自身权限范围相关的操作日志。

## 16. 数据口径

- 当前温度：城市最近一次同步到的实时温度。
- 体感温度：数据源返回的体感温度，如无则展示为空。
- 降雨概率：当前或未来指定时段的降水概率。
- 告警级别：按蓝色、黄色、橙色、红色从低到高展示，列表以当前最高级别排序。
- 今日告警数：当前自然日内生成的告警事件数量，包含已关闭和已忽略。
- 待处理告警数：状态为待处理或通知失败的告警事件数量。
- 数据延迟：当前时间与最近同步时间差值超过配置阈值。
- 通知成功率：指定时间范围内通知成功数 / 通知任务总数。
- 重点城市：在城市配置中标记为重点城市的城市集合。

## 17. 异常与边界场景

- 查询无结果时，列表展示空状态，并保留当前筛选条件。
- 天气数据延迟时，详情页展示最近更新时间和延迟提示。
- 城市映射缺失时，列表展示“数据缺失”，并提示系统管理员补充城市编码。
- 数据源同步失败时，展示失败原因和重试入口。
- 同一城市同一类型告警重复同步时，系统应合并或标记重复，避免重复通知。
- 告警已关闭后再次收到同类高级别告警时，应生成新告警或重新打开，规则需可配置。
- 告警处理时状态已被他人更新，系统应阻止提交并提示刷新。
- 订阅规则重复时，系统阻止保存并提示冲突规则。
- 通知接收人为空或渠道不可用时，系统阻止发送。
- 通知失败时，保留失败原因并允许重试。
- 用户无权限导出、关闭告警或维护配置时，操作不可见或置灰并提示权限不足。
- 后台接口失败时，页面保留当前上下文并展示错误反馈。

## 18. 非功能要求

- 性能：常规列表查询应在 3 秒内返回；复杂筛选可展示加载态。
- 稳定性：告警确认、通知发送、关闭告警和同步重试必须具备幂等能力。
- 可追踪：告警处理、通知发送、导出、订阅配置、数据源重试和权限变更必须记录操作日志。
- 安全性：数据源密钥、Webhook 地址等敏感配置不得明文展示。
- 可扩展：天气类型、告警级别、城市分组、同步阈值和订阅渠道应配置化。
- 可用性：接口失败、同步延迟、通知失败时应提供明确原因和重试入口。
- 一致性：后台文案使用中文，页面形态后续设计应遵循 Boss Ledger 主题和 Ant Design 组件规则。

## 19. 验收标准

- 当运营人员进入天气概览时，系统展示重点城市天气、今日告警数、待处理告警数和数据同步状态。
- 当用户输入城市名称并点击“查 询”时，系统返回匹配城市天气记录。
- 当用户选择告警级别为“红色”时，列表仅展示当前存在红色告警的城市或事件。
- 当城市天气无匹配数据时，表格展示空状态，筛选条件不被清空。
- 当用户点击城市天气行“查看详情”时，系统打开详情抽屉并展示实况、未来预报、小时级预报、空气质量、生活指数和告警记录。
- 当系统同步到新的天气告警时，应生成告警事件并进入“待处理”状态。
- 当用户处理告警但未填写处理意见时，系统阻止提交。
- 当用户忽略告警但未填写忽略原因时，系统阻止提交。
- 当用户点击“发送通知”时，系统根据订阅规则生成通知任务，并记录通知结果。
- 当通知失败时，系统展示失败原因，并允许有权限用户重试。
- 当告警已关闭时，系统不允许重复关闭，并提示状态已更新。
- 当用户新增订阅规则时，系统校验业务线、城市范围、天气类型、告警级别、通知渠道和接收人。
- 当订阅规则重复时，系统阻止保存并提示冲突规则。
- 当数据源同步失败时，数据源监控列表展示失败状态、失败原因和重试入口。
- 当系统管理员点击“重试同步”时，系统触发同步任务并记录操作日志。
- 当无导出权限用户进入页面时，导出操作不可见或不可点击。
- 当有导出权限用户点击导出时，系统按当前筛选条件生成导出任务并记录日志。
- 当用户无权限处理告警或维护配置时，对应操作不可见或置灰并展示权限不足反馈。

## 20. 合理假设

- 用户只提供了“天气系统原型”，未提供具体业务线、目标用户、城市范围、气象供应商、接口边界和设计稿。
- 本 PRD 默认面向 Boss Ledger 后台运营场景，不是 C 端天气 App，也不是 YOP 开放平台 API 文档。
- 本期以原型和需求基线为目标，天气数据可使用 mock 数据或后续接入的第三方数据源。
- 当前日期按工作区日期使用 2026-07-10。
- 告警级别参考常见蓝色、黄色、橙色、红色分级，但不代表正式气象监管口径。
- 天气预报准确性、灾害研判、气象算法和外部供应商服务稳定性不在本期承诺范围内。
- Product Only 模式按规则仅输出 `proposal.md`，不生成 `preview.html`，也不生成生产代码。
