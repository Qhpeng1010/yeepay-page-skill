# Proposal: 新增结算记录查询页面

## 1. Original Request

使用 yeepay-page-skill，帮我分析“结算记录查询页面”这个需求，只输出 proposal.md，不需要页面设计和前端代码。

## 2. Requirement Understanding

用户希望为 Boss Ledger 后台新增一个结算记录查询页面，用于运营或财务人员按条件筛选、查看和导出商户结算记录。

本次仅输出产品方案 `proposal.md`，不输出页面设计、任务拆解、前端实现或自检文档。

## 3. Target Theme

- Theme: boss-ledger
- Reason: 需求包含“结算记录”“查询页面”等 Boss Ledger 运营后台关键词，按主题选择规则使用 `specs/themes/boss-ledger.md`。

## 4. Background

结算记录是商户资金结算过程中的核心数据。运营和财务人员需要在后台快速查询商户结算批次、结算金额、结算状态、结算账户和失败原因，以便处理商户咨询、财务核对、异常排查和导出对账。

当前需求聚焦“查询”场景，优先建立统一的结算记录检索入口。

## 5. Goals

- 支持运营和财务人员按商户、结算单号、时间、状态等条件查询结算记录。
- 支持查看单条结算记录的关键资金信息和处理结果。
- 支持导出符合筛选条件的结算记录，满足对账和线下处理需要。
- 明确结算状态和异常处理信息，降低人工排查成本。

## 6. Users / Roles

- 财务人员：查询结算金额、结算账户、结算状态，用于核对和对账。
- 运营人员：查询商户结算记录，用于处理商户咨询和日常运营支持。
- 客服人员：查询结算结果和失败原因，用于响应商户问题。
- 系统管理员：根据权限查看全量结算记录和导出记录。

默认角色：Boss Ledger 后台运营人员。

## 7. Scope

### In Scope

- 结算记录查询。
- 查询条件重置。
- 结算记录列表展示。
- 结算状态展示。
- 查看单条结算记录详情。
- 按筛选条件导出结算记录。
- 查询无结果、加载失败、导出失败、权限不足等异常处理。

### Out of Scope

- 不支持新建结算记录。
- 不支持编辑结算记录。
- 不支持手工发起结算。
- 不支持结算规则配置。
- 不支持结算账户变更。
- 不支持批量重试、批量审核或批量打款。
- 不输出页面设计和前端代码。

## 8. Business Object

业务对象：结算记录。

结算记录表示一次面向商户的资金结算结果，通常包含结算单号、商户信息、结算周期、结算金额、手续费、实际到账金额、结算账户、结算状态和处理时间等信息。

## 9. Core Workflow

1. 用户进入结算记录查询页面。
2. 系统默认展示最近一段时间的结算记录列表。
3. 用户输入查询条件，如结算单号、商户编号、商户名称、结算状态、结算时间。
4. 用户点击“查 询”。
5. 系统返回符合条件的结算记录列表。
6. 用户可点击“重 置”清空查询条件并恢复默认列表。
7. 用户可点击单条记录的“查看”进入详情查看结算明细。
8. 有导出权限的用户可点击“导 出”或“下载Excel”，系统按当前筛选条件导出数据。

## 11. Status

| Status | Meaning | Available Actions |
|---|---|---|
| 待处理 | 结算任务已生成，尚未开始处理 | 查看 |
| 处理中 | 系统正在处理结算 | 查看 |
| 结算成功 | 结算已完成且资金处理成功 | 查看、导出 |
| 结算失败 | 结算处理失败，需要排查失败原因 | 查看、导出 |
| 已取消 | 结算任务被取消，不再继续处理 | 查看 |

状态流转建议：

- 待处理 -> 处理中 -> 结算成功
- 待处理 -> 处理中 -> 结算失败
- 待处理 -> 已取消

本次不包含人工重试或状态修改能力。

## 12. Permissions

- 查看权限：运营人员、财务人员、客服人员、系统管理员可查看结算记录列表。
- 详情权限：具备结算记录查看权限的用户可查看单条详情。
- 导出权限：仅财务人员、系统管理员或被授权运营人员可导出结算记录。
- 敏感字段权限：结算账户、实际到账金额等字段按系统权限展示；无权限时应脱敏或隐藏。
- 删除权限：本页面不提供删除结算记录能力。
- 二次确认：导出大量数据时需要二次确认，并提示导出范围。

## 13. Edge Cases

- 查询无结果：列表展示空状态，并提示用户调整筛选条件。
- 数据加载失败：展示错误反馈，允许用户重新查询。
- 查询条件不合法：如时间范围过大或格式错误，系统阻止查询并提示原因。
- 导出失败：展示失败提示，说明可重试或联系管理员。
- 权限不足：导出按钮不可见或不可点击，并提示无导出权限。
- 状态已变更：用户查看详情时，如果状态已变化，详情展示最新状态。
- 金额为空或异常：金额字段展示为 `-`，避免展示错误数值。
- 结算账户缺失：账户信息展示为 `-`，详情中说明账户信息缺失。
- 网络异常：保留当前查询条件，提示网络异常并允许重试。

## 14. Acceptance Criteria

- 当运营人员输入结算单号并点击“查 询”时，系统应返回匹配的结算记录列表。
- 当财务人员选择结算状态为“结算失败”并点击“查 询”时，系统应展示符合条件的失败记录。
- 当用户点击“重 置”时，系统应清空查询条件并恢复默认列表。
- 当列表无数据时，表格区域应展示空状态。
- 当用户点击单条记录“查看”时，系统应展示该结算记录的详情信息。
- 当有导出权限的用户点击“导 出”或“下载Excel”时，系统应按当前筛选条件导出结算记录。
- 当无导出权限的用户进入页面时，导出操作应不可见或不可点击。
- 当查询失败时，系统应展示错误反馈并保留用户已输入的查询条件。
- 当结算金额、手续费、实际到账金额展示时，系统应使用金额格式并保留两位小数。
- 当结算状态为“结算失败”时，系统应展示失败原因或明确提示暂无失败原因。
