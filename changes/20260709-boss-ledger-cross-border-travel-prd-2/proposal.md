# 需求方案：Boss Ledger 跨境旅游业务运营后台 PRD

## 1. 原始需求

`/yeepay:prd 输一个跨境旅游业务的prd`

---

## 2. 需求理解

本次需求是输出一份“跨境旅游业务”的产品需求文档。用户未指定 C 端旅游预订页面、YOP 开放平台能力或具体生产工程，因此按 Yeepay Page Skill 的 `/yeepay:prd` 路由进入 Product Only 模式，并默认选择 Boss Ledger 运营后台主题。

本 PRD 面向易宝支付跨境旅游业务运营场景，重点覆盖订单运营、资源确认、游客材料、跨境支付核验、退款退订、改期处理、合规风控、供应商对账与操作留痕。文档目标是形成可进入页面设计、研发拆解、接口梳理和业务评审的需求基线，不包含生产代码实现。

---

## 3. 目标主题

- 主题：Boss Ledger
- 选择原因：需求未包含 YOP、开放平台、API 文档、开发者中心等关键词；“跨境旅游业务”更适合落到后台订单、履约、退款、对账、合规和风控处理场景。按默认规则选择 Boss Ledger，并在合理假设中明确说明。

---

## 4. 背景说明

跨境旅游业务通常包含境外酒店、国际机票、签证、保险、当地玩乐、接送机、门票、自由行套餐、跟团游等多种产品形态。与国内单一交易相比，跨境旅游存在产品组合复杂、目的地多、供应商分散、币种多、时区差异、确认时效不稳定、退订规则复杂、游客证件材料敏感、合规风控要求高、供应商对账口径复杂等特点。

当前若订单、支付、材料、供应商确认、退款退订、对账和合规审核分散在多个系统或依赖人工表格处理，会带来以下问题：

- 运营无法快速识别确认超时、库存失败、材料缺失和出行临近的风险订单。
- 客服处理退订、改期和客诉时缺少统一订单上下文。
- 财务核对用户支付、供应商采购、退款、服务费、汇差和结算状态成本较高。
- 风控和合规对高风险目的地、异常支付、证件异常、名单命中、频繁退订等风险缺少集中处理入口。
- 高风险操作如手工确认、退款金额调整、汇率调整、材料下载和导出缺少统一权限、二次确认和日志留痕。

因此需要建设 Boss Ledger 跨境旅游业务运营后台，将订单全链路和关键处理动作统一到一个可查询、可处理、可追踪、可审计的后台模块。

---

## 5. 业务目标

- 建立统一的跨境旅游订单运营入口，支持运营、客服、财务、风控、合规基于同一订单视图协同处理。
- 提升异常订单识别效率，集中暴露确认超时、确认失败、材料缺失、出行临近、触达失败、退款异常和对账差异。
- 缩短资源确认和人工介入链路，降低漏确认、重复确认和出行前未完成履约的风险。
- 支持多币种金额、汇率、锁汇、服务费、采购金额、退款金额和汇差的清晰展示，提升财务核对效率。
- 建立退款退订和改期处理闭环，明确申请、审核、供应商确认、手续费、补差价、退款结果和通知状态。
- 支持高风险目的地、证件异常、名单命中、金额异常、频繁退订和跨境限额风险的审核处理。
- 对敏感数据查看、材料下载、导出、手工确认、退款金额调整、汇率调整、合规放行等操作实现权限控制和操作日志。

## 6. 使用用户 / 角色

| 角色 | 使用场景 | 核心诉求 | 主要操作 | 权限边界 |
|---|---|---|---|---|
| 跨境旅游运营人员 | 监控订单履约、资源确认、材料交付和供应商异常 | 快速定位异常订单并完成处理 | 查询订单、查看详情、重新确认、转人工、上传材料、刷新供应商状态、备注跟进 | 不可确认结算，不可调整汇率，不可查看超授权敏感信息 |
| 客服人员 | 用户咨询、退订、改期、补资料和客诉处理 | 获取完整订单上下文并给出处理结果 | 查询订单、查看通知记录、发起退订、发起改期、补充备注、触达用户 | 默认仅查看脱敏信息，金额调整需主管权限 |
| 客服主管 | 审批退订、改期、手续费和特殊退款 | 控制退款风险并保障用户处理效率 | 审核退订、审核改期、调整手续费、确认退款方案 | 金额调整必须二次确认并记录日志 |
| 财务人员 | 核对支付、采购、退款、服务费、汇差和供应商账单 | 快速识别对账差异和结算风险 | 查看金额明细、供应商对账、标记差异、下载对账明细 | 不可处理履约确认和合规放行 |
| 风控人员 | 处理异常支付、频繁退款、疑似套现和风险订单 | 识别风险并阻断异常履约 | 查看风险记录、审核风险任务、冻结处理、驳回放行 | 仅处理风控任务，不维护供应商与汇率配置 |
| 合规人员 | 审核目的地、游客身份材料、名单命中和跨境合规信息 | 防止不合规订单继续履约 | 查看合规任务、审核通过、审核驳回、填写审核意见 | 审核意见必填，敏感信息查看留痕 |
| 系统管理员 | 维护基础配置和权限 | 保证业务规则、供应商和权限可控 | 维护供应商、目的地风险等级、产品类型、币种、汇率来源、角色权限 | 不直接处理业务订单，配置变更需记录 |

## 7. 业务范围

### 7.1 本期范围

- 跨境旅游订单查询列表：支持组合查询、重置、列设置、分页、排序、导出、查看详情。
- 订单详情抽屉：展示订单基础信息、游客信息、产品行程、支付汇率、资源确认、材料、退订改期、合规风控、对账和操作日志。
- 资源确认监控：支持待确认、确认中、确认成功、确认失败、确认超时、转人工、重新确认和刷新状态。
- 游客与出行材料管理：支持材料状态展示、材料上传、下载、审核通过、审核驳回、补充材料通知和交付状态记录。
- 跨境支付核验：展示支付币种、用户支付金额、结算币种、供应商采购金额、交易汇率、锁汇状态、服务费、汇差、支付渠道和支付流水。
- 退款退订处理：支持退订申请、退订审核、供应商退订、手续费计算、退款金额确认、部分退款、退款结果同步和通知状态。
- 改期处理：支持改期申请、新出行日期确认、资源差额、补差价支付状态、供应商改期结果和改期完成记录。
- 合规风控审核：支持高风险目的地、名单命中、证件异常、金额异常、频繁退订、跨境限额等审核任务。
- 供应商对账：支持按供应商、产品类型、目的地、交易日期、出行日期、币种、结算状态查询对账明细，标记差异并导出。
- 权限与日志：覆盖敏感信息查看、导出、退款调整、汇率调整、手工确认、合规放行、材料下载等高风险操作。

### 7.2 非本期范围

- 不建设 C 端跨境旅游搜索、比价、预订、行程选择、游客资料填写和支付页面。
- 不建设商户端旅游产品发布、库存维护、价格管理和营销配置页面。
- 不建设 YOP 开放平台 API 文档、SDK、开发者接入和商户自助联调能力。
- 不做真实境外酒店、航司、地接社、签证中心、保险公司或聚合供应商接口联调。
- 不做真实购汇、结汇、锁汇交易、跨境付款、资金清分和银行通道处理。
- 不实现完整合规规则引擎、制裁名单系统、反洗钱模型和审批流配置后台。
- 不生成正式 React + TypeScript 生产代码，不生成 `preview.html`。

## 8. 业务对象

- 跨境旅游订单：平台侧主订单，承载用户、商户、产品、金额、状态和履约主线。
- 商户订单：商户侧传入的业务订单，用于和商户系统对账。
- 供应商订单：境外供应商或聚合供应商返回的履约订单。
- 游客 / 出行人：姓名、联系方式、证件、出生日期、国籍、材料等敏感信息主体。
- 旅游产品：酒店、机票、签证、保险、当地玩乐、接送机、门票、套餐等。
- 行程资源：出行日期、目的地、酒店、航班、项目、人数、房型、票种等。
- 支付单：用户支付流水、渠道、币种、金额、支付状态。
- 汇率与锁汇记录：交易汇率、锁汇状态、汇率来源、汇差。
- 退款单：退款申请、退款金额、退款币种、退款状态和渠道结果。
- 退订申请：退订原因、规则、手续费、供应商确认结果和审核记录。
- 改期申请：新出行日期、差额、补差价支付状态和供应商改期结果。
- 出行材料：护照、签证材料、保险凭证、酒店确认单、电子票券、行程单等。
- 合规审核任务：目的地风险、名单命中、证件异常、跨境限额等审核任务。
- 风控风险记录：异常支付、频繁退订、疑似套现、金额异常等风险记录。
- 供应商账单 / 结算单：供应商采购、退款、服务费、汇差和结算状态。
- 通知记录：短信、邮件、站内信、商户回调等触达记录。
- 操作日志：人工操作、状态变更、金额调整、材料下载、导出和审核记录。

## 9. 核心业务流程

### 9.1 订单履约主流程

1. 用户在商户侧完成跨境旅游产品下单，商户向平台提交订单。
2. 用户完成支付，系统生成支付单并记录支付币种、金额、渠道和交易汇率。
3. 系统根据产品类型、目的地、游客材料和合规规则判断是否可自动提交供应商确认。
4. 若材料完整且未命中风险规则，系统向供应商发起资源确认。
5. 供应商返回确认成功后，订单进入履约中，系统生成或接收出行凭证。
6. 若供应商确认失败或超时，订单进入异常队列，运营可重新确认、转人工或取消并触发退款。
7. 出行材料完成并交付用户后，订单等待出行。
8. 出行完成或业务结束后，订单进入待对账，财务进入供应商对账流程。

### 9.2 退款退订流程

1. 用户、客服或商户发起退订申请。
2. 系统读取产品退订规则，计算可退金额、供应商手续费、平台手续费和预计退款金额。
3. 客服或运营审核退订申请，涉及特殊金额调整时需要主管权限。
4. 系统向供应商提交退订，等待供应商确认。
5. 供应商确认后，系统生成退款单并同步支付退款结果。
6. 退款成功后更新订单退款状态、通知用户并记录操作日志。
7. 若退款失败、手续费异常或供应商结果不一致，进入异常队列。

### 9.3 改期流程

1. 用户或客服提交改期申请，填写目标出行日期和改期原因。
2. 系统校验订单状态、产品规则、出行日期、供应商支持情况和材料有效期。
3. 系统查询或人工确认新资源价格，计算补差价或退差价。
4. 存在补收差额时，用户完成差额支付后才允许提交供应商改期。
5. 供应商确认改期成功后，系统更新行程、凭证和通知记录。
6. 供应商改期失败时，订单恢复原状态或进入人工处理。

### 9.4 合规风控流程

1. 系统在下单、支付、确认、退订、改期和导出等节点执行风险识别。
2. 命中高风险目的地、名单、证件异常、金额异常、频繁退订或跨境限额规则时，生成审核任务。
3. 风控或合规人员进入任务详情，查看风险原因、订单信息、游客信息和历史记录。
4. 审核通过后订单继续履约；审核驳回后订单暂停履约并进入取消或退款流程。
5. 审核结果、意见、附件和操作人写入日志。

### 9.5 供应商对账流程

1. 财务按供应商、币种、交易日期、出行日期或结算周期查询待对账订单。
2. 系统展示平台采购金额、供应商账单金额、退款金额、服务费、汇差和结算状态。
3. 金额、币种、汇率、订单状态或退款状态不一致时，系统标记对账差异。
4. 财务可上传供应商账单凭证、填写差异说明并发起复核。
5. 差异处理完成后，财务确认结算并下载对账明细。

## 14. 核心操作规则

| 操作 | 触发位置 | 前置条件 | 操作结果 | 风险控制 |
|---|---|---|---|---|
| 查询 | 订单列表、审核列表、对账列表 | 用户有页面访问权限 | 按条件刷新列表 | 保留查询条件 |
| 导出 | 列表工具栏 | 用户有导出权限 | 生成导出任务 | 记录导出条件、操作人、时间 |
| 查看详情 | 表格操作列主操作 | 用户有查看权限 | 打开详情抽屉 | 敏感字段默认脱敏 |
| 查看完整证件 | 详情抽屉 | 用户有敏感信息查看权限 | 展示完整证件号 | 二次确认并记录查看日志 |
| 重新确认 | 资源确认抽屉 | 订单为确认失败或确认超时 | 状态变为确认中 | 二次确认，防重复提交 |
| 转人工 | 资源确认抽屉 | 订单需要人工介入 | 生成人工处理任务 | 必填处理原因 |
| 取消订单 | 订单详情 / 确认异常处理 | 订单未确认成功或合规驳回 | 订单取消并视情况触发退款 | 二次确认，记录原因 |

| 退订审核通过 | 退订处理抽屉 | 退订规则校验通过 | 提交供应商退订 | 金额变更需二次确认 |
| 退订审核驳回 | 退订处理抽屉 | 退订申请不满足规则 | 退订申请关闭 | 驳回原因必填 |
| 调整手续费 | 退订处理抽屉 | 用户有主管权限 | 更新退款方案 | 二次确认并记录前后金额 |
| 确认改期 | 改期处理抽屉 | 新资源可用，补差价已支付或无需补差 | 提交供应商改期 | 记录新旧行程 |
| 合规审核通过 | 合规任务详情 | 用户有合规 / 风控权限 | 订单恢复后续履约 | 审核意见必填 |
| 合规审核驳回 | 合规任务详情 | 风险不可放行 | 订单进入合规驳回 | 审核意见必填 |
| 标记对账差异 | 供应商对账列表 | 财务有对账权限 | 结算状态变为对账差异 | 差异原因必填 |
| 确认结算 | 供应商对账列表 | 无对账差异或差异已处理 | 结算状态变为已结算 | 二次确认并留痕 |

## 15. 权限要求

- 页面访问：仅授权的跨境旅游运营、客服、财务、风控、合规和系统管理员可访问。
- 订单查看：各角色按数据范围查看订单，默认隐藏完整手机号、证件号、出生日期、护照有效期和材料附件。
- 敏感信息查看：查看完整手机号、证件号、游客材料和护照有效期需要专项权限，必须二次确认并记录日志。
- 材料下载：下载签证材料、护照扫描件、保险凭证、酒店确认单等文件需要下载权限。
- 资源确认：重新确认、转人工和取消已支付订单仅运营人员或运营主管可操作。
- 退款退订：退订审核、手续费调整、退款金额调整由客服主管或运营主管操作，涉及金额变化必须二次确认。
- 改期处理：改期确认和补差价核验由运营人员处理，特殊差额调整需主管权限。
- 合规风控：风险审核和合规放行仅风控、合规角色可操作，审核意见必填。
- 汇率操作：汇率查看面向运营和财务开放；汇率调整、重新锁汇和汇差标记仅财务主管或系统管理员可操作。
- 对账结算：供应商对账和确认结算仅财务人员可操作。
- 导出权限：订单明细、游客信息、对账明细、操作日志导出均需独立权限，导出记录可审计。
- 系统配置：供应商、目的地风险、产品类型、币种、汇率来源和高风险操作开关仅系统管理员维护。

## 16. 数据口径

- 用户支付金额：用户通过支付渠道实际支付的金额，包含支付币种。
- 供应商采购金额：平台需向供应商支付或结算的采购金额，按供应商结算币种展示。
- 平台服务费：平台向商户或订单收取的服务费，需区分交易服务费、退订服务费和其他服务费。
- 交易汇率：订单支付或采购计算时使用的汇率，需记录汇率来源和生效时间。
- 锁汇状态：未锁汇、已锁汇、锁汇失败、无需锁汇。
- 汇差金额：因交易汇率、结算汇率或退款汇率变化产生的差额。
- 可退金额：订单实付金额扣除供应商手续费、平台手续费和已消费资源后的预计退款金额。
- 对账差异：平台订单金额、供应商账单金额、退款金额、币种、汇率或订单状态不一致。
- 出行临近订单：距离出行日期小于等于配置阈值且仍存在待确认、材料待补充、材料待审核、合规待审核或凭证未交付状态的订单。

## 17. 异常与边界场景

- 查询无结果时，列表展示空状态，并保留当前筛选条件。
- 供应商确认接口超时但后续返回成功时，系统应防止重复确认，并提示状态已更新。
- 支付成功但资源确认失败时，订单进入确认异常队列，允许运营重新确认、转人工或取消并退款。
- 确认成功后用户取消订单时，应进入退订流程，不允许直接取消。
- 出行日期临近但材料缺失时，系统应置顶风险提示并允许通知补充。
- 游客证件信息不完整时，系统阻止提交供应商履约。
- 材料审核驳回未填写原因时，系统阻止提交。
- 合规审核驳回未填写意见时，系统阻止提交。
- 退订手续费高于可退金额时，系统禁止提交并提示核对规则。
- 改期存在补收差额且用户未支付时，系统禁止提交供应商改期。
- 锁汇失败或汇率过期时，订单进入人工处理队列，禁止自动确认跨币种采购金额。
- 用户联系方式缺失或通知发送失败时，系统标记触达失败并允许人工备注。
- 平台数据与供应商账单金额、币种或状态不一致时，系统标记对账差异，禁止直接确认结算。
- 命中高风险目的地、名单或跨境限额规则时，订单暂停自动履约。
- 用户无权限查看敏感信息、下载材料或导出数据时，操作不可见或置灰并提示权限不足。
- 多人同时处理同一订单时，后提交操作应进行状态版本校验，失败后提示刷新。
- 后台接口失败时，页面保留当前上下文并展示错误反馈。

## 18. 非功能要求

- 性能：常规查询在 3 秒内返回；复杂组合查询可展示加载态并允许取消或重试。
- 稳定性：高风险状态变更必须幂等，避免重复确认、重复退款、重复结算。
- 可追踪：所有人工操作、审核、导出、敏感信息查看、金额调整、状态变更都必须记录日志。
- 安全性：敏感字段默认脱敏；导出文件应有权限控制、水印或下载有效期。
- 可扩展：产品类型、目的地风险等级、供应商、币种、汇率来源和确认超时阈值应配置化。
- 国际化数据：支持多币种金额展示，但后台界面文案按 Boss Ledger 要求使用中文。
- 审计：合规、风控、退款、汇率、对账等关键操作可按订单、操作人、时间和操作类型追溯。
- 容错：供应商接口异常、通知失败、支付退款状态延迟时，应提供重试、转人工和备注能力。

## 19. 验收标准

- 当运营人员输入订单编号并点击“查询”时，系统应返回匹配的跨境旅游订单。
- 当运营人员选择目的地、产品类型、供应商和出行日期后点击“查询”时，系统应按组合条件筛选订单。
- 当资源确认状态选择“确认超时”时，列表仅展示确认超时订单。
- 当查询无匹配数据时，表格展示空状态，筛选条件不被清空。
- 当用户点击订单行“查看详情”时，系统打开详情抽屉并展示订单、游客、产品、支付、汇率、资源确认、材料、退订改期、合规风控、对账和操作日志。
- 当待确认订单点击“重新确认”时，系统展示二次确认；确认后订单进入“确认中”并记录操作日志。
- 当订单已确认成功时，系统不展示“直接取消订单”，应展示退订或改期入口。
- 当游客材料缺失时，订单展示“材料待补充”，并阻止自动提交供应商履约。
- 当材料审核驳回未填写原因时，系统阻止提交并提示填写驳回原因。
- 当订单命中高风险目的地、名单或跨境限额规则时，系统生成合规 / 风控审核任务，审核通过前不得自动履约。
- 当合规审核驳回未填写审核意见时，系统阻止提交。
- 当退订手续费大于可退金额时，系统阻止提交并提示“退订金额异常，请核对规则”。
- 当改期申请存在补收差额且用户未支付时，系统禁止提交供应商改期。
- 当退款金额被人工调整时，系统要求二次确认并记录调整前金额、调整后金额、操作人和原因。
- 当财务查看供应商对账列表时，系统按供应商、币种、交易日期和出行日期展示采购金额、退款金额、服务费、汇差和结算状态。
- 当平台金额、币种、汇率或状态与供应商账单不一致时，系统标记“对账差异”，并禁止直接确认结算。
- 当无导出权限用户进入页面时，导出操作不可见或不可点击，并给出权限不足反馈。
- 当有导出权限用户点击导出时，系统按当前筛选条件生成导出任务并记录导出日志。
- 当用户查看完整证件号或下载游客材料时，系统校验权限、二次确认并记录查看或下载日志。
- 当接口失败时，页面展示失败反馈，并允许用户保留筛选条件后重试。

## 20. 合理假设

- 用户只提供了“跨境旅游业务的 PRD”，未提供具体公司内部系统、页面范围、接口边界和业务策略。
- 本 PRD 默认面向 Boss Ledger 后台运营场景，不是 C 端旅游产品，也不是 YOP 开放平台开发者文档。
- 业务模型按“商户接入平台、平台聚合跨境旅游资源、供应商履约、易宝支付承接支付与后台运营”的模式设计。
- 当前日期按工作区日期使用 2026-07-09。
- 酒店、机票、签证、保险、当地玩乐、接送机、门票和套餐在本期统一纳入跨境旅游订单后台，后续可按产品类型拆分独立子模块。
- 多币种、汇率、锁汇、汇差和供应商结算在本 PRD 中只定义后台展示和处理口径，不代表真实外汇交易、购汇、结汇或跨境付款方案。
- 合规和风控能力只定义后台审核入口和任务处理，不替代正式合规规则引擎、名单系统或反洗钱模型。
- Product Only 模式按规则仅输出 `proposal.md`，不生成 `preview.html`，也不生成生产代码。
