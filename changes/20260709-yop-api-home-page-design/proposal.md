# Proposal: YOP API 首页页面设计方案

## 1. Original Request

使用 yeepay-page-skill，帮我做一个 YOP API 首页的页面设计方案，不用写代码，输出html给我预览

## 2. Requirement Understanding

用户希望按 `yeepay-page-skill` 规范，为 YOP 开放平台输出一个 API 首页页面设计方案，并提供可直接打开预览的静态 HTML。用户明确“不用写代码”，因此不改 `open-platform` 工程业务代码；HTML 仅作为设计预览稿。

## 3. Target Theme

- Theme: yeepay-开放平台-DESIGN
- Reason: 需求明确包含 “YOP” 与 “API 首页”，属于开放平台、开发者中心和 API 文档类页面，应使用 `specs/themes/yeepay-开放平台-DESIGN.md`。

## 4. Background

YOP API 首页是开发者进入开放平台 API 能力、接口文档和接入流程的核心入口。页面需要同时解决“找 API”“理解能力范围”“开始接入”“查看开发资源”和“获知接口变更”几个高频问题。

现有 `open-platform` 已包含 API 搜索、API 集成流程、接口文档分类等模块。本设计方案在这些业务基础上加强首页的信息聚合能力，使开发者从首屏即可进入搜索、热门 API、能力分类、接入流程和辅助资源。

## 5. Goals

- 让开发者进入页面后 3 秒内明确这里是 YOP API 能力入口。
- 支持按 API 名称、接口标识、错误码、SDK、回调等关键词搜索。
- 用分类和高频 API 缩短开发者找接口的路径。
- 将接入流程、SDK、错误码、示例代码、回调说明等关键资源前置。
- 用状态、版本、更新时间和公告提示提高技术可信度。

## 6. Users / Roles

- 开发者：搜索 API、阅读文档、进入调试和示例代码。
- 技术负责人：评估接口能力范围、稳定性和接入成本。
- 解决方案人员：按场景为商户或合作方推荐能力。
- 产品运营人员：维护推荐 API、公告、分类和更新信息。
- 平台管理员：管理 API 状态、文档入口和展示排序。

## 7. Scope

### In Scope

- API 首页信息架构。
- 首屏搜索、热门搜索和 API 动态。
- API 能力分类导航。
- 高频 API / 推荐 API 入口。
- API 集成流程。
- SDK、错误码、示例代码、签名验签、回调通知等开发资源入口。
- 最新更新 / 公告模块。
- 空、加载、异常、无权限等状态说明。
- 静态 HTML 预览稿。

### Out of Scope

- 不改 `open-platform` 业务代码。
- 不实现 Vue / React / TypeScript 页面。
- 不设计完整 API 详情页。
- 不实现在线调试器、创建应用、密钥配置、生产开通等完整流程。
- 不定义真实接口协议和后端数据结构。

## 8. Business Object

业务对象：YOP API 能力与 API 文档入口。

核心对象包括：

- API 分类
- API 条目
- API 状态
- 接入流程
- SDK 资源
- 示例代码
- 错误码文档
- API 动态 / 更新公告

## 9. Core Workflow

1. 用户进入 YOP API 首页。
2. 用户在首屏通过搜索框输入 API 名称、接口标识、错误码或文档关键词。
3. 用户可点击热门搜索词或 API 动态进入对应文档。
4. 用户可从 API 分类中进入支付、退款、分账、商户进件、账户、对账、通知回调等能力域。
5. 用户可从高频 API 卡片进入 API 详情、调试或接入申请。
6. 用户可查看 API 集成流程，继续进入配置应用、配置密钥、下载 SDK、沙箱联调、调用记录和上线清单。
7. 用户可从开发资源区进入 SDK、错误码、示例代码、签名验签、回调说明、FAQ。
8. 用户可通过公告模块查看重要变更和更新日志。

## 10. Fields

| Field | Type | Required | Description | Example |
|---|---|---|---|---|
| API 名称 | String | Yes | API 展示名称 | 统一支付下单 |
| API 标识 | String | Yes | API 唯一标识或接口编码 | yop.pay.order.create |
| API 分类 | Enum | Yes | API 所属能力分类 | 支付 |
| API 描述 | String | Yes | API 能力说明 | 用于创建一笔支付订单 |
| 请求方法 | Enum | No | API 请求方式 | POST |
| API 状态 | Enum | Yes | 当前 API 可用状态 | 可用 |
| 版本 | String | No | API 当前版本 | v1.0 |
| 适用环境 | Enum | No | 支持沙箱、生产或全部环境 | 沙箱 / 生产 |
| 更新时间 | DateTime | No | 文档或 API 最近更新时间 | 2026-07-08 |
| 推荐标识 | Boolean | No | 是否推荐在首页展示 | 是 |
| 相关资源 | Link[] | No | SDK、示例代码、错误码等链接 | Java SDK |

## 11. Status

| Status | Meaning | Available Actions |
|---|---|---|
| 可用 | API 当前可正常接入 | 查看文档、调试接口、申请接入 |
| Beta | API 处于试用或灰度阶段 | 查看文档、申请试用 |
| 即将下线 | API 已有替代方案，未来会停止维护 | 查看迁移说明、查看替代 API |
| 已下线 | API 不再支持新接入 | 查看历史说明 |
| 维护中 | API 暂时不可用或文档维护中 | 查看公告、稍后重试 |

## 12. Permissions

- 未登录用户：可浏览公开 API 分类、基础说明、公告和部分接入指南。
- 已登录开发者：可查看完整 API 文档、SDK、示例代码和接入说明。
- 已认证商户或合作方：可申请接入、创建应用、获取密钥、进入调试流程。
- 平台管理员：可维护 API 分类、推荐排序、展示状态和更新公告。
- 敏感操作如获取密钥、生产环境开通、应用创建，不在 API 首页直接完成，应跳转到对应流程。

## 13. Edge Cases

- API 列表加载失败：展示错误提示和重试入口。
- 搜索无结果：展示空状态，并推荐检查关键词或查看全部分类。
- 分类为空：隐藏空分类或展示“暂无 API”说明。
- API 即将下线：展示状态标识和迁移说明入口。
- API 已下线：保留历史说明，不展示“申请接入”主操作。
- 用户未登录：涉及接入申请、调试、密钥相关操作时引导登录。
- 用户无权限：展示权限说明和申请入口。
- 外部资源链接失效：展示错误提示，并提供反馈入口。

## 14. Acceptance Criteria

- 当开发者进入 YOP API 首页时，页面应展示搜索入口、API 分类、高频 API、接入流程、开发资源和最新更新。
- 当开发者输入 API 名称或关键词搜索时，系统应返回匹配的 API 或文档资源。
- 当搜索无结果时，页面应展示空状态并提供查看全部 API 分类的入口。
- 当开发者点击某个 API 条目时，系统应跳转到对应 API 详情页。
- 当 API 状态为“即将下线”时，页面应展示状态标识和迁移说明入口。
- 当用户未登录并点击“申请接入”时，系统应引导用户登录。
- 当 API 数据加载失败时，页面应展示错误反馈和重试入口。
- 当页面展示 SDK、错误码、示例代码入口时，点击后应进入对应文档页面。

## 15. Assumptions

- 本需求明确指定 YOP，因此使用 YOP 开放平台主题。
- “API 首页”按文档中心页处理，并结合 API 导航首页能力，不按普通后台查询列表页处理。
- API 详情页、开发者中心和控制台入口已存在，本次只设计首页跳转入口。
- HTML 文件是设计预览稿，不作为生产实现。
- 预览稿使用静态内容模拟真实 API 分类、状态和公告。
