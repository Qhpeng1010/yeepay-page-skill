# 自由组合晋级配方流程

本流程用于把一次通过人工验收的自由组合页面，判断并转换为可重复生成的参数化配方。配方不是新的设计规则；三本老板管账导演规则仍然是唯一的设计语义来源。

## 角色边界

- 设计师决定是否晋级、晋级范围、固定结构和可变参数。
- 工程实现确定性解析器、配方编译器、Page Spec 契约和静态回归。
- 业务人员确认页面的视觉和交互是否符合业务目标。
- 未通过人工验收的页面不得晋级；未晋级的页面继续走受控自然语言生成。

## 晋级判断

满足以下条件才进入配方评估：

- 至少有一个完整页面经过人工视觉和交互验收。
- 页面结构在不同业务对象之间保持稳定，变化主要是字段、列、文案、样例数据和明确操作。
- 交互可以由有限参数表达，不依赖一次性脚本、隐藏状态或特殊人工操作。
- 所需能力已经开放，且组合没有违反导演规则的禁用边界。
- 可以为命中和不命中情况分别写出确定性测试。

出现复杂联动、远程校验、特殊权限、跨页面事务或一次性视觉结构时，默认不晋级。

## 固定步骤

### 1. 记录人工验收结果

在原 Change 的 `review.md` 中记录：

- 人工查看的页面和视口。
- 已确认的业务场景和操作结果。
- 已确认的状态、错误、危险确认和上下文保持行为。
- 未确认或暂不支持的边界。

### 2. 提炼结构与参数

设计师填写配方评估记录，明确：

- 固定页面结构和主流程。
- 可变字段、列、分组、状态、样例数据和文案。
- 可选操作及其启用条件。
- 不允许进入配方的特殊差异。
- 对应的三本导演规则 Rule ID。

### 3. 做晋级决策

设计师只能做以下两种决定：

- `promote`：结构稳定，允许实现参数化配方。
- `keep-freeform`：保留为自由组合场景，不进入配方。

决定必须写入评估记录，不能由解析器根据关键词自动晋级。

### 4. 实现确定性配方

工程按评估记录新增或修改：

- 自然语言解析器。
- 参数化编译器。
- Page Spec 能力和契约校验。
- 只启用需求明确声明的操作。
- 不命中边界时返回受控回退，不猜测、不拼装替代页面。

配方实现不得新增独立视觉规则；布局、组件和交互优先引用导演规则及其编译执行层。

### 5. 补齐回归资料

同时新增：

- `recipe-regression-prompts.md` 中的配方提示词。
- 配方解析、编译和端到端静态测试。
- 至少一个命中样例和一个不命中样例。
- `review.md` 中的人工验收待办或已确认结果。

### 6. 登记稳定组合

只有配方回归和人工验收都通过后，才在 `generation-policy.json` 的 `validatedCombinations` 中登记组合，并标记 `evidence: manual-business`。

随后刷新发布清单，运行入口、策略、Page Spec、能力场景和工程完整性检查，再提交和推送。

## 禁止事项

- 不能因为页面生成过一次就自动创建配方。
- 不能把历史 Change、截图或 Figma 作为配方规则来源。
- 不能用宽松关键词直接回放页面快照。
- 不能把未开放能力包装成配方参数。
- 不能让配方编译器覆盖三本导演规则的冲突决策。

## 结果

配方晋级完成后，后续相似需求应在统一入口中快速命中；未命中或超出参数边界的需求，继续进入受控自然语言生成，并重新接受人工验收。
