# Page Templates Spec

## Purpose

本文件定义 Yeepay Page Skill 可使用的标准页面模板。

页面模板用于解决：

> 当前需求应该使用什么页面结构？

本文件只负责页面结构、适用场景、模块顺序、默认字段、默认操作和模板选择规则。

本文件不负责具体视觉表现。颜色、间距、导航样式、Tabs 样式、查询区样式、表格区样式等，以 `specs/design-system.md` 和当前选中的 `specs/themes/{theme}.md` 为准。

---

## When to Use

当用户提出以下需求时，必须读取本文件：

- 新增页面
- 修改页面
- 生成页面方案
- 生成前端实现
- 生成 PRD
- 判断页面类型
- 根据一句话需求生成页面

---

## Template Selection Rules

处理需求时，必须先判断页面类型。

如果用户未明确说明页面类型，按以下优先级选择：

1. 查询列表页
2. 审核处理页
3. 详情页
4. 表单新建页
5. 表单编辑页
6. 配置管理页
7. 数据看板页
8. 分步流程页
9. 文档中心页
10. API 详情页

如果一个需求包含多个页面，需要在 `page-design.md` 中明确页面关系。

例如：

- 列表页 + 详情抽屉
- 列表页 + 新增弹窗
- 列表页 + 编辑页
- 查询页 + 数据看板
- 文档列表页 + API 详情页

---

## Template Output Requirements

在 `changes/{change-id}/page-design.md` 中必须说明：

1. 选择的页面模板
2. 选择原因
3. 页面结构
4. 核心模块
5. 查询条件
6. 表格字段
7. 表单字段
8. 状态设计
9. 页面级操作
10. 行内操作
11. 异常状态
12. 与当前 theme 的关系

---

# Template 1: 查询列表页

## Use Case

适用于后台数据查询、筛选、查看和操作场景。

常见页面：

- 商户列表
- 订单列表
- 结算记录
- 交易流水
- 审核记录
- 操作日志
- 配置列表
- 风险记录
- 任务列表

## Page Structure

1. 页面标题区或 Tabs 区
2. 查询条件区
3. 列表工具栏
4. 数据表格
5. 分页
6. 行内操作

## Default Query Fields

根据业务对象选择：

- 编号
- 名称
- 类型
- 状态
- 创建时间
- 更新时间
- 操作人

## Default Table Fields

默认字段包括：

- 编号
- 名称
- 类型
- 状态
- 创建时间
- 更新时间
- 操作

## Default Page Actions

- 查 询
- 重 置
- 新 增
- 导 出

## Default Row Actions

- 查看
- 编辑
- 删除
- 启用
- 停用

## Rules

- 查询条件区位于列表上方。
- 表格用于承载主要数据。
- 操作列固定放在最后。
- 行内操作超过 3 个时，应使用更多操作收纳。
- 删除、停用、撤销等风险操作必须二次确认。
- 具体查询区、表格区视觉表现以当前 theme 为准。

# Template 2: 审核处理页

## Use Case

适用于资料审核、资质审核、风控审核、订单审核、配置审核等场景。

常见页面：

- 商户资料审核
- 结算资料审核
- 账户变更审核
- 风险资料审核
- 交易异常审核

## Page Structure

1. 页面标题区或 Tabs 区
2. 查询条件区
3. 审核列表
4. 审核详情入口
5. 审核操作弹窗或抽屉
6. 审核结果反馈

## Default Query Fields

- 审核单号
- 业务编号
- 商户编号
- 商户名称
- 审核状态
- 提交时间

## Default Table Fields

- 审核单号
- 业务对象
- 商户编号
- 商户名称
- 资料类型
- 提交时间
- 审核状态
- 操作

## Default Status

- 待审核
- 审核通过
- 审核驳回

## Default Actions

- 查看
- 审核
- 通过
- 驳回

## Rules

- 驳回操作必须填写驳回原因。
- 审核通过和审核驳回必须二次确认。
- 已审核数据不可重复审核。
- 审核完成后列表状态需要更新。
- 审核操作必须有成功或失败反馈。

---

# Template 3: 详情页

## Use Case

适用于展示单个业务对象的完整信息。

常见页面：

- 商户详情
- 订单详情
- 结算单详情
- 账户详情
- 审核详情
- 配置详情

## Page Structure

1. 页面标题区
2. 基础信息区
3. 状态信息区
4. 业务信息区
5. 操作记录区
6. 底部操作区

## Rules

- 信息应按业务含义分组。
- 重要状态应靠前展示。
- 字段较多时应使用分组结构。
- 操作记录通常放在页面下方。
- 返回操作应清晰可见。
- 如详情只是辅助查看，可优先使用 Drawer。

---

# Template 4: 表单新建页

## Use Case

适用于新建配置、新增记录、发起申请、创建任务等场景。

## Page Structure

1. 页面标题区
2. 表单基础信息区
3. 表单业务信息区
4. 上传或配置区
5. 底部操作区

## Default Actions

- 保 存
- 提 交
- 取 消

## Rules

- 必填项必须明确标识。
- 表单项必须有校验规则。
- 提交前必须校验。
- 保存和提交需要明确区分。
- 离开页面前如有未保存内容，需要提示。

---

# Template 5: 表单编辑页

## Use Case

适用于修改已有业务对象或配置项。

## Page Structure

1. 页面标题区
2. 当前对象基础信息
3. 可编辑表单区
4. 底部操作区

## Default Actions

- 保 存
- 取 消

## Rules

- 编辑页必须回显当前数据。
- 不可编辑字段需要置灰或只读。
- 保存前需要校验。
- 保存成功后需要反馈。
- 重要字段修改需要二次确认。

---

# Template 6: 配置管理页

## Use Case

适用于系统参数、业务规则、开关、模板等配置管理。

常见页面：

- 产品配置
- 支付配置
- 通知配置
- 权限配置
- 风控规则配置
- 文档配置

## Page Structure

1. 页面标题区
2. 配置分组
3. 配置列表或配置表单
4. 操作区
5. 修改记录

## Default Actions

- 新 增
- 编辑
- 删除
- 启用
- 停用
- 保存

## Rules

- 配置项必须展示状态。
- 高风险配置修改必须二次确认。
- 配置修改后应有操作记录。
- 启用和停用应有明确反馈。
- 配置项较多时应分组展示。

---

# Template 7: 数据看板页

## Use Case

适用于统计分析、运营概览、风险概览、数据监控等场景。

## Page Structure

1. 页面标题区
2. 筛选条件区
3. 核心指标区
4. 图表区
5. 明细列表区

## Rules

- 指标必须有明确名称和单位。
- 图表必须说明数据含义。
- 数据为空时需要展示空状态。
- 图表与明细数据口径需要一致。
- 看板页面不应过度装饰，仍需保持业务可读性。

---

# Template 8: 分步流程页

## Use Case

适用于需要多步骤完成的流程。

常见页面：

- 商户进件
- 资料补充
- 配置向导
- 批量导入
- 接入流程

## Page Structure

1. 页面标题区
2. 步骤条
3. 当前步骤内容
4. 底部操作区

## Default Actions

- 上一步
- 下一步
- 保 存
- 提 交
- 取 消

## Rules

- 每一步必须有明确标题。
- 当前步骤必须清晰高亮。
- 下一步前需要校验当前步骤。
- 提交前需要展示确认信息。
- 用户返回上一步时不应丢失已填写内容。

---

# Template 9: 文档中心页

## Use Case

适用于开放平台、产品文档、开发者中心、帮助中心等文档阅读场景。

常见页面：

- 产品文档中心
- 接入指南
- 帮助文档
- 开发者中心首页
- 文档搜索结果页

## Page Structure

1. 顶部导航
2. 左侧文档目录
3. 中间文档内容区
4. 右侧锚点目录
5. 搜索入口
6. 相关文档推荐

## Default Modules

- 文档目录
- 文档标题
- 更新时间
- 正文内容
- 步骤说明
- 提示信息
- 相关链接

## Rules

- 文档中心页优先保证阅读效率。
- 左侧目录需要支持层级展示。
- 右侧锚点用于当前页面快速定位。
- 内容区不应过度后台化。
- 具体视觉表现以 YOP 或当前文档类 theme 为准。

---

# Template 10: API 详情页

## Use Case

适用于 API 文档、接口详情、错误码说明、接入示例等技术文档场景。

## Page Structure

1. API 名称
2. API 描述
3. 请求方法
4. 请求地址
5. 接入场景
6. 请求参数
7. 响应参数
8. 请求示例
9. 响应示例
10. 错误码
11. 注意事项
12. 相关文档

## Default Tables

请求参数表：

- 参数名
- 类型
- 是否必填
- 说明
- 示例值

响应参数表：

- 参数名
- 类型
- 说明
- 示例值

错误码表：

- 错误码
- 错误说明
- 处理建议

## Rules

- API 详情页必须突出接入效率。
- 请求参数、响应参数、错误码必须结构清晰。
- 示例代码必须和参数说明一致。
- 代码块应支持复制。
- 不应把 API 详情页做成普通后台查询列表页。
- 具体视觉表现以 YOP 或当前 API 文档类 theme 为准。

---

## Page Template Checklist

生成页面方案前必须检查：

- [ ] 是否选择了明确页面模板
- [ ] 是否说明选择原因
- [ ] 是否复用了标准页面结构
- [ ] 是否明确页面模块顺序
- [ ] 是否明确默认字段
- [ ] 是否明确默认操作
- [ ] 是否明确状态设计
- [ ] 是否考虑异常状态
- [ ] 是否避免创造不受控的新结构
- [ ] 是否说明视觉表现以当前 theme 为准
