# Quality Spec

## Purpose

本文件只定义跨系统的交付质量底线。页面选择、视觉、组件细节、交互规则、能力门禁和验收案例必须以已路由系统的规则和执行校验为准。

## Review Output

`changes/{change-id}/review.md` 至少记录：

1. 需求、页面设计和页面规格是否一致。
2. 当前系统的规则、能力策略和规格校验是否通过。
3. 预览是否已生成，以及自动预检和人工验收分别完成到什么程度。
4. 已知限制、能力缺口或未验证场景。
5. 最终结论：`pass` 或 `failed`。

未获得人工确认时，不得将整体视觉或浏览器交互标记为通过。任一适用硬门禁失败时，最终结论必须为 `failed`。

## Common Checklist

- [ ] 需求对象、用户、范围、状态和风险明确。
- [ ] 已使用当前系统的页面选择规则和能力策略。
- [ ] 交付文件与当前 Page Spec 或实现源一致。
- [ ] 必填、格式、危险确认、成功和失败反馈满足需求。
- [ ] 预览可打开，且不混用其他系统资产或规则。
- [ ] 自动预检结果和人工验收范围已明确区分。
- [ ] 未把历史 Change、历史设计稿或共享文档当成系统规则来源。

## Decision

只有当前系统的适用校验全部通过，且已记录剩余人工验收状态时，才可交付。系统专属检查命令、截图要求和浏览器回归由该系统的交互与验收规则及执行适配器决定。
