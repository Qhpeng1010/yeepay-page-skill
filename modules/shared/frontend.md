# Frontend Engineering Spec

## Purpose

本文件只定义跨系统的前端工程原则，不定义任一系统的视觉、模板、页面布局、固定 Shell 或验证命令。

生成页面时，只执行已路由系统 `domain.json` 返回的资源和命令。系统的导演规则、Page Spec、渲染器、组件库和运行时边界都由该系统自身声明。

## Implementation Principles

1. 业务数据、表单值和状态必须有清晰的数据结构。
2. loading、空数据、错误、成功和权限受限状态必须可表达。
3. 真实接口接入前，mock 数据应贴近预期数据结构。
4. 不得手写替代已选组件库已提供的基础交互控件。
5. 不得修改固定渲染器、固定 Shell、主题或构建生成物来解决单页需求。

## Preview Rules

- 页面交付默认生成可独立浏览的预览，除非用户明确要求不输出 HTML。
- 预览是评审产物，不等同于生产代码。
- 预览使用的资源、组件库、Shell、资产和构建方式只能来自当前系统适配器返回的执行边界。
- Page Spec 模式只编辑 `page-spec.json`；预览、样式、运行时和资产均由固定构建器生成。
- 非 Page Spec 的实现方式以当前系统的执行命令和规则为准。

## Interaction Rules

预览应实现当前需求的关键任务路径，并能表达查询、重置、提交、关闭、分页、状态反馈等适用交互。不得为了演示补充未经业务需求和能力策略允许的操作。
