## 0. 规范说明

本规范根据 Figma 文件中的 8 个、宽度均为 `1440 px` 的桌面端长页面提取。

规则分为三个可信等级：

- **已提取**：可从 Figma 节点、样式或重复页面中直接测得。
- **已归一**：Figma 中存在多个相近值，本规范将其收敛为统一 Token 或组件规则。
- **建议补充**：源文件未形成明确规范，但为了响应式、无障碍和 AI 稳定生成需要增加。

### 0.1 当前 Figma 规范化程度

源文件已建立 7 个本地颜色样式：

- 主色
- 一级文字颜色
- 二级文字颜色
- 三级文字颜色
- 四级文字颜色
- 辅助蓝色
- 橘色

当前未建立：

- Figma Variables
- 本地文字样式
- 本地阴影样式
- 本地栅格样式
- 本地组件及组件变体

页面中使用了较多外部组件实例，包括按钮、菜单、搜索、Anchor、分割线和 Ant Design 图标。因此，本规范既记录视觉事实，也负责把外部实例与 YOP 自有页面规则统一起来。

## 1. 品牌与体验定位

### 1.1 产品气质

YOP 是面向企业客户、合作伙伴和开发者的开放平台。整体视觉应传达：

- 专业可靠
- 技术开放
- 能力丰富
- 接入高效
- 企业级稳定
- 清晰可理解

### 1.2 设计原则

1. **业务价值先于技术细节**  
   营销型页面先说明能解决什么问题，再说明能力、流程和接口。

2. **开发路径必须清晰**  
   文档与 API 页面要帮助用户快速定位“准备、配置、开发、调试、排障、上线”的当前位置。

3. **长页面依靠结构而不是装饰组织内容**  
   使用明确标题层级、卡片分组、锚点目录和足够留白，避免依赖复杂背景切割信息。

4. **主色集中用于路径引导**  
   蓝色用于当前导航、主要操作、链接和流程节点，不能让每个区块都成为高强调区域。

5. **官网与文档中心共享品牌，不共享同一信息密度**  
   官网偏展示与转化；文档中心偏阅读与查找。两者使用统一 Token，但采用不同页面骨架。

## 2. 页面体系

YOP 页面分为两套基础框架。

### 2.1 Marketing Shell

适用于：

- 官网首页
- 平台指引
- 解决方案列表
- SaaS 服务商、平台商、连锁、集团、商户等角色详情
- 品牌案例与接入流程页面

基本结构：

```text
全局主导航
Hero / 页面头图
可选的分类导航
模块化内容区
售前咨询 CTA
全局页脚
```

### 2.2 Documentation Shell

适用于：

- 文档中心首页
- API 首页
- 接入准备
- 开发工具与平台规范
- 行业方案文档
- 产品服务文档

基本结构：

```text
全局主导航              60
文档二级导航            52
──────────────────────────
左侧目录 256
正文区域
右侧本文目录
```

### 3.2 官网内容区

- 标准内容容器宽度为 `1200 px`。
- 在 `1440 px` 画布上，容器左右各保留 `120 px`。
- 内容型模块的标准上下内边距为 `80–120 px`。
- Hero 典型高度为 `540–640 px`。
- 普通展示模块典型高度为 `440–840 px`，由内容决定。
- 不允许为了对齐不同页面而固定整页高度。

### 3.3 文档中心内容区

文档中心在主导航与二级导航之后，从 `y = 112 px` 开始：

```text
左侧目录：256 px

右侧工作区：1184 px
├── 左右内边距：48 px
├── 正文：906 px
├── 间距：32 px
└── 本文目录：150 px
```

规则：

- 左侧目录可独立滚动或吸顶。
- 正文标题和内容均从工作区的 `48 px` 内边距起始。
- 右侧本文目录在长文档中保持可见。
- 正文与本文目录使用横向布局，不能通过绝对定位模拟。
- 版权信息位于文档正文底部，不进入右侧本文目录。

### 3.4 响应式断点

源文件只提供了 `1440 px` 桌面稿，以下为建议补充：

| 断点 | 行为 |
| --- | --- |
| `≥ 1280 px` | 完整桌面布局，1200 px 最大内容区 |
| `1024–1279 px` | 左右页边距缩小至 48–64 px |
| `768–1023 px` | 官网卡片降列；文档右侧目录隐藏 |
| `< 768 px` | 主导航折叠；左侧目录改抽屉；内容单列 |

禁止在窄屏中等比例缩小 1440 页面。

| Token | 建议值 | 用途 |
| --- | --- | --- |
| `color.status.success` | `#22AC38` | 成功和有效 |
| `color.status.error` | `#E41A37` | 错误和危险 |
| `color.status.warning` | `#FA541C` | 警告 |
| `color.status.info` | `#1162E6` | 信息提示 |

#### 颜色使用规则

- 主色是页面行动路径色，不是大面积背景色。
- 主按钮、选中导航、链接和流程编号可以使用主色。
- 同一区块最多保留一个主色操作。
- 青色和橙色用于插画或不同能力类型的辅助区分，不承担通用交互语义。
- 浅蓝背景必须与白色卡片形成清晰层级。
- 不允许把插画中的品牌色自动提升为新的 UI Token。

### 4.2 字体

#### 字体栈

```css
font-family:
  "PingFang SC",
  -apple-system,
  BlinkMacSystemFont,
  "Segoe UI",
  "Microsoft YaHei",
  Arial,
  sans-serif;
```

源文件字体构成：

- 中文主体：PingFang SC
- 英文与部分数字：Roboto、Inter、Montserrat

归一规则：

- 产品界面和中文内容统一使用系统字体栈。
- Montserrat 只用于大数字、序号或品牌化英文数据。
- Roboto/Inter 不作为中文页面的独立正文体系。

#### 字号层级

| Token | 字号 | 字重 | 建议行高 | 用途 |
| --- | ---: | --- | ---: | --- |
| `type.display` | 48 px | Semibold | 56–64 px | 少量首页核心数据或超大标题 |
| `type.hero` | 40 px | Semibold | 48–56 px | Hero 主标题 |
| `type.h1` | 32 px | Semibold | 44–48 px | 页面标题 |
| `type.h2` | 24 px | Semibold | 34–40 px | 模块标题 |
| `type.h3` | 20 px | Medium | 28–32 px | 卡片组标题、文档二级标题 |
| `type.h4` | 18 px | Medium | 26–28 px | 卡片标题、文档三级标题 |
| `type.body-large` | 16 px | Regular | 24 px | Hero 说明、重要正文 |
| `type.body` | 14 px | Regular | 22 px | 默认正文、导航与组件文字 |
| `type.caption` | 12–13 px | Regular | 18–20 px | 日期、版权与辅助说明 |

#### 字重

- Regular：正文、说明、导航默认态。
- Medium：卡片标题、模块小标题、选中导航。
- Semibold：页面标题、Hero 标题、核心数据。
- Bold：仅用于少量大数字和营销数据，不用于普通按钮。

#### 文字规则

- 默认正文使用 `14/22 px`。
- 长文档正文建议使用 `14–16 px`，行宽不得超过正文列。
- 链接使用主色，不依赖下划线；正文内链接在 Hover 时增加下划线。
- 文章标题不得使用营销型超大字号。
- 不使用全大写英文作为主要中文标题。

### 4.3 间距

采用 `4 px` 基础单位。

| Token | 数值 | 用途 |
| --- | ---: | --- |
| `space.1` | 4 px | 标题与标签微间距 |
| `space.2` | 8 px | 图标与文字、紧凑列表 |
| `space.2_5` | 10 px | 按钮内部和常用小间距 |
| `space.3` | 12 px | 表单、标签、提示 |
| `space.4` | 16 px | 组件标准间距 |
| `space.6` | 24 px | 卡片内边距、内容组 |
| `space.8` | 32 px | 文档正文与目录、卡片组 |
| `space.10` | 40 px | 大内容组、文档章节 |
| `space.12` | 48 px | 官网区块内部结构 |
| `space.16` | 64 px | 小型页面区块 |
| `space.20` | 80 px | 标准官网区块上下留白 |
| `space.25` | 100 px | 大型官网区块上下留白 |
| `space.30` | 120 px | 页面左右页边距、大型留白 |

规则：

- 卡片内边距优先使用 `24 px` 或 `32 px`。
- 官网模块上下留白优先使用 `80 px`、`100 px` 或 `120 px`。
- 文档章节间距使用 `40 px`。
- 组件内部不得使用 `49 px`、`101 px` 等偶发值作为新 Token。

### 4.4 圆角

| Token | 数值 | 用途 |
| --- | ---: | --- |
| `radius.small` | 4 px | 按钮、标签、输入框 |
| `radius.medium` | 8 px | 图片、普通卡片 |
| `radius.large` | 16 px | 营销能力卡片、重点内容卡 |
| `radius.pill` | 999 px | 胶囊标签、圆形按钮 |

源文件高频圆角为 `4 / 8 / 16 px`，应作为唯一主要圆角梯度。

### 4.5 阴影

| Token | 数值 | 用途 |
| --- | --- | --- |
| `shadow.card` | `0 0 8px rgba(0,0,0,0.06)` | 普通卡片 |
| `shadow.brand-card` | `0 0 8px rgba(17,98,230,0.16)` | 轻量品牌强调 |
| `shadow.brand-float` | `0 0 24px rgba(17,98,230,0.12)` | 浮层/重点展示 |
| `shadow.header` | `0 2px 0 rgba(0,0,0,0.04)` | 吸顶导航分隔 |

## 5. 全局组件

### 5.1 全局主导航

| 属性 | 规则 |
| --- | --- |
| 高度 | 60 px |
| 背景 | 白色；Hero 叠加时可使用约 64% 白色并配合模糊 |
| 左侧 | 易宝支付 Logo + “开放平台” |
| 主菜单 | 首页、平台指引、解决方案、文档中心、API |
| 右侧 | 全局搜索、控制台、登录 |
| 当前项 | 主色文字 + 底部主色指示线 |

交互规则：

- 导航吸顶时增加细分割或轻阴影。
- 当前页面必须唯一高亮。
- “登录”为高强调入口时可使用主色背景。
- 全局搜索不替代文档内搜索。
- 主导航项保持单行。

### 5.2 文档二级导航

| 属性 | 规则 |
| --- | --- |
| 高度 | 52 px |
| 背景 | 白色 |
| 左侧 | 文档中心 / 当前业务域 |
| 右侧或中部 | 接入准备、接入指引、API 文档、工具支持、平台规范等 |
| 分隔 | 底部轻分割线 |

二级导航与主导航共同组成 `112 px` 的文档顶部框架。

### 5.3 按钮

#### Primary

- 主色背景 `#1162E6`
- 白色文字
- 圆角 `4 px`
- 高度建议：
  - Medium：`32 px`
  - Large：`40 px`
- 左右内边距：
  - Medium：`16 px`
  - Large：`20–24 px`

#### Secondary

- 白色或透明背景
- `rgba(0,0,0,0.16)` 边框
- 一级文字色
- Hover 时使用主色边框与主色文字

#### Link action

- 主色文字
- 可配右箭头
- 不使用按钮背景

规则：

- 一个模块只保留一个主要按钮。
- 按钮文字保持常规或 Medium，不使用重粗体。
- 不允许用图片模拟按钮。

### 5.4 搜索框

全局搜索：

- 位于主导航右侧。
- 默认浅灰背景。
- 高度约 `32–36 px`。
- 支持关键词、文档和 API 搜索入口。

文档内搜索：

- 位于左侧目录顶部。
- 宽度随 `256 px` 侧栏适配。
- 搜索结果属于当前文档域。

搜索页 Hero：

- 用于文档中心或 API 首页。
- 可使用大尺寸搜索框。
- 必须明确搜索范围。

### 5.5 Tabs / 分类导航

适用于行业切换、角色切换和场景切换。

- 默认文字：二级文字色。
- 选中：主色文字、浅蓝背景或底部主色指示线。
- 高度以 `32–40 px` 为主。
- 标签间距 `16–24 px`。
- 超出一行时应支持水平滚动或更多菜单，不换成不规则多行。

### 5.6 Card

#### Feature Card

- 背景：白色或浅灰。
- 圆角：`16 px`。
- 内边距：`24–32 px`。
- 图标区：主色或业务辅助色。
- 标题：`18–20 px Medium`。
- 描述：`14 px`。
- 行动：Link action。

#### Image Card

- 图片在上，内容在下。
- 图片圆角与卡片顶部保持一致。
- 典型用于客户案例、行业与角色。
- 卡片内容高度应保持同组对齐。

#### Compact Document Card

- 圆角：`8 px`。
- 内边距：`16–24 px`。
- 用于文档中心入口和 API 产品分类。
- 信息密度高于营销卡片。

### 5.7 Step / Process

首页接入流程使用 4 步结构：

1. 入网签约
2. 环境准备
3. 开发调试
4. 正式上线

规则：

- 序号使用主色大数字。
- 步骤标题 `18–20 px Medium`。
- 说明文字 `14 px`。
- 步骤之间用细线或箭头连接。
- 每一步最多一个行动入口。
- 窄屏下改为纵向时间轴。

### 5.8 CTA Banner

用于售前咨询：

- 居中布局。
- 典型上下内边距 `80 px`。
- 标题中可用主色突出“售前咨询”。
- 一行说明 + 一个 Primary 按钮。
- 背景可使用轻量浅蓝渐变，不加入复杂交互内容。

### 5.9 Footer

| 属性 | 规则 |
| --- | --- |
| 典型高度 | 296 px |
| 内容宽度 | 1200 px |
| 左侧 | Logo、客服电话、版权 |
| 右侧 | 平台指引、服务与支持、常用链接 |
| 上内边距 | 24 px |
| 左右内边距 | 120 px |
| 下内边距 | 48 px |

页脚文字以 `12–14 px` 为主，链接 Hover 使用主色。

## 6. 文档中心组件

### 6.1 左侧目录

| 属性 | 规则 |
| --- | --- |
| 宽度 | 256 px |
| 起始位置 | 主导航与二级导航下方 |
| 背景 | 白色/极浅灰 |
| 搜索 | 顶部固定 |
| 一级组 | 可展开收起 |
| 当前项 | 浅蓝背景 + 主色文字 + 右侧主色竖线 |

规则：

- 目录支持至少三级层级。
- 当前页面路径必须自动展开。
- 收起按钮位于侧栏与正文交界处。
- 收起后正文区域扩展。
- 菜单文字不加粗，选中态使用 Medium。

### 6.2 Breadcrumb

- 位于正文标题上方。
- `14 px`，三级文字色。
- 当前页面不应表现为链接。
- 路径过长时保留首尾并折叠中间层级。

### 6.3 文章标题区

结构：

```text
Breadcrumb
H1 页面标题
摘要/适用范围
可选流程概览
```

规则：

- H1：`32 px Semibold`。
- 摘要：`14–16 px`，二级文字色。
- 标题区与正文第一章节间距 `32–40 px`。

### 6.4 本文目录

| 属性 | 规则 |
| --- | --- |
| 宽度 | 150 px |
| 与正文间距 | 32 px |
| 标题 | “本文内容” |
| 当前项 | 主色文字或左侧主色标记 |

规则：

- 根据正文 H2/H3 自动生成。
- 随滚动更新当前章节。
- 不显示超过三级的层级。
- 在低于 `1024 px` 时隐藏或转为悬浮目录。

### 6.5 文档标题层级

| 层级 | 样式 | 用途 |
| --- | --- | --- |
| H1 | 32 px Semibold | 文档页标题 |
| H2 | 24 px Semibold | 一、二、三等核心章节 |
| H3 | 20 px Medium | 章节内主题 |
| H4 | 18 px Medium | 具体步骤或语言方案 |
| Body | 14 px / 22 px | 正文与列表 |

禁止仅通过加粗正文模拟标题。

### 6.6 Flow Overview

文档中的流程概览使用水平步骤标签：

```text
商户入网并签约产品
→ 密钥配置
→ SDK 集成
→ 开发对接
→ 测试验证
→ 正式上线
```

规则：

- 主色描边或浅蓝底。
- 节点文字 `14 px`。
- 箭头只表达顺序，不作为可点击图标。
- 窄屏改为纵向步骤。

### 6.7 Alert

类型：

- Info：浅蓝背景 + 信息图标
- Warning：浅橙背景 + 警告图标
- Error：浅红背景 + 错误图标
- Success：浅绿背景 + 成功图标

基础规则：

- 圆角 `4–8 px`。
- 内边距 `12–16 px`。
- 图标与文字间距 `8 px`。
- 提示必须说明影响和下一步动作。

### 6.8 Code / API content

虽然源文件以业务文档为主，后续 API 页面应遵循：

- 代码字体使用等宽字体。
- 代码区与正文有明确背景区分。
- 提供复制按钮。
- 参数表支持横向滚动。
- 请求与响应示例必须标注语言/格式。
- 错误码与排查建议关联展示。

### 6.9 文档反馈

右侧目录上方可显示“文档对你是否有帮助？”：

- 是 / 否 两个轻量按钮。
- 提交后显示感谢或原因选项。
- 反馈不能阻塞阅读。

### 6.10 上一篇 / 下一篇

- 位于正文底部。
- 左右分布。
- 展示文章标题。
- 不得使用浏览器历史作为唯一导航方式。

## 8. 交互规则

### 8.1 导航

- 主导航与二级导航在长页面中保持可访问。
- 当前页面和当前栏目必须同时明确。
- Anchor 点击后滚动至目标章节，并预留吸顶导航高度。
- 浏览器返回后应恢复滚动位置。

### 8.2 卡片

- 整卡可点击时，卡片内不要再放多个相互竞争的链接。
- Hover 使用轻微阴影、边框或位移，位移不超过 `2 px`。
- 图片卡片不能因图片比例不同而破坏同组高度。

### 8.3 搜索

- 输入后提供关键词联想。
- 区分文档、API、产品和解决方案结果。
- 无结果时提供拼写建议、热门入口或分类导航。
- 搜索结果保留关键词高亮。

### 8.4 左侧目录

- 展开/收起不应刷新页面。
- 选中项始终可见。
- 目录收起后保留恢复入口。
- 深层目录不能依赖 Hover 才可访问。

### 8.5 长文档

- 标题可生成锚点。
- 复制锚点后应提供轻提示。
- 表格、代码和大图在窄容器中支持横向滚动。
- 不使用无限滚动加载核心文档内容。

---

## 9. 内容规范

### 9.1 标题

- Hero 标题表达价值，不堆叠产品名。
- 模块标题表达用户能获得的结果。
- 文档标题表达任务或主题。
- API 标题使用准确接口或能力名称。

### 9.2 描述

- 营销卡片描述控制在 2–4 行。
- 文档摘要说明适用对象、目标和结果。
- 避免“赋能、闭环、抓手”等无具体含义的连续表达。

### 9.3 CTA

推荐：

- 立即接入
- 立即咨询
- 查看详情
- 查看指引
- 查看 API 文档
- 开始对接

不推荐：

- 点击这里
- 了解更多内容
- 去看看

### 9.4 数据表达

- 关键数据必须带单位和说明。
- `2000+`、`50+`、`99.999%` 等数字需对应可解释指标。
- 同一组数据使用统一数字字体和对齐方式。

---

## 10. 无障碍

- 普通文字对比度至少达到 `4.5:1`。
- 大字号文字对比度至少达到 `3:1`。
- 所有可点击区域最小为 `40 × 40 px`，触控设备建议 `44 × 44 px`。
- 主导航、侧栏、Tabs 和本文目录必须支持键盘访问。
- 当前导航不能只依赖蓝色表达，需配合下划线、背景或竖线。
- 图片必须提供替代文本。
- 装饰性图片使用空替代文本。
- 视频提供字幕、播放状态和键盘控制。
- 文档标题结构必须符合 H1 → H2 → H3 层级。
- 搜索、菜单展开、目录收起等状态需被读屏识别。
- 动效遵循 `prefers-reduced-motion`。

## 12. AI 页面生成契约

### 12.1 强制读取顺序

生成页面前必须读取：

1. 品牌与体验定位
2. 页面体系
3. 布局与栅格
4. Design Tokens
5. 全局组件
6. 对应页面模板
7. 交互和无障碍规则

### 12.2 路由规则

| 用户意图 | 必须选择的模板 |
| --- | --- |
| YOP 首页、开放能力首页 | Template 01 |
| 合作伙伴、平台、商户角色选择 | Template 02 |
| 全部行业或解决方案入口 | Template 03 |
| 单个角色、行业或场景详情 | Template 04 |
| 文档聚合入口 | Template 05 |
| API 聚合与接口分类 | Template 06 |
| 接入准备、开发工具、平台规范文章 | Template 07 |
| 餐饮、夜经济、能源等行业文档 | Template 08 |

每个页面只能有一个主模板。允许组合模板内的可选模块，不允许把官网 Shell 和 Documentation Shell 混成同一页面骨架。

### 12.3 允许替换

- 页面标题与说明
- 行业、角色和场景数据
- 卡片数量及业务文案
- 图片和插画
- 客户 Logo
- 文档章节内容
- API 分类与接口条目
- CTA 文案与目标链接

### 12.4 禁止修改

没有明确设计系统变更时，不得修改：

- `#1162E6` 主色
- 1440 基准下的 1200 px 官网内容区
- 60 px 主导航
- 52 px 文档二级导航
- 256 px 文档左侧目录
- 文档正文与本文目录的三栏关系
- `4 / 8 / 16 px` 圆角梯度
- 一级至四级文字透明度体系
- 当前导航的唯一选中原则
- 页脚信息结构
- 文档标题层级和锚点逻辑

### 12.5 生成前检查

- 是否先确定 Marketing Shell 或 Documentation Shell？
- 是否选择了唯一主模板？
- 页面内容是否位于正确最大宽度内？
- 是否存在且仅存在一个模块主操作？
- 导航当前项是否唯一？
- 标题层级是否正确？
- 长文本是否具备可读行高？
- 卡片是否使用统一圆角和内边距？
- 文档目录能否展开、收起和定位当前项？
- 右侧本文目录是否由标题自动生成？
- 图片、图标和视频是否具备无障碍信息？
- 是否提供 Hover、Focus、Loading、Empty 和 Error 状态？
- 窄屏是否采用重排而非缩放？

## 13. 源文件问题与升级建议

当前页面视觉语言已基本统一，但还不是可直接复用的完整设计系统。建议按以下优先级升级：

### P0 — 影响稳定生成

1. 将主色、文字色、背景色、间距和圆角建立为 Variables。
2. 建立官网与文档中心两个独立 Shell 组件。
3. 将全局主导航、文档二级导航、左侧目录和页脚组件化。
4. 为 8 类页面模板建立明确命名，避免多个画板继续使用“SAAS服务商/平台连锁/商户详情页”。
5. 建立 AI 页面模板路由，强制唯一主模板。

### P1 — 影响维护效率

1. 建立文字样式。
2. 将按钮、卡片、Tabs、流程、Anchor、Alert 建立为组件变体。
3. 统一近似字号、圆角和偶发间距。
4. 区分外部 Ant Design 组件与 YOP 自有组件。
5. 为文档正文建立代码块、表格、参数、错误码等专项组件。

### P2 — 影响多端质量

1. 补充 1024、768 和移动端响应式稿。
2. 补充 Hover、Focus、Loading、Empty、Error 状态。
3. 补充导航吸顶、侧栏收起和锚点滚动原型。
4. 补充长文档、超长 API 名称、超多分类和搜索无结果场景。

在上述 Figma 系统化工作完成前，本 `DESIGN.md` 作为从当前页面归一得到的 YOP 页面生成基准。
